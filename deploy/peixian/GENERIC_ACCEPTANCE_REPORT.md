# 通用 Agent 平台 V1 验收记录

日期：2026-09-15。分支：`codex/generic-agent-platform`。开发起点：三角色检查点 `e924f1af27a16e52e589b016f4eb52da259ba5d0`。交付源码提交、镜像归档内部 ID 与文件摘要以离线包 `release-manifest.json`、`SHA256SUMS` 为准。

## 验收范围与环境

本轮验证通用账号平台、插件固定服务连接、单服务器交付工具。原正式项目 A～G 业务方案不作为本版前置条件；案件、资料域、部门审批、业务 Run、专项数据接口与固定分析报告未在本轮建设。

执行环境是 Windows 主机上的 Docker Desktop Linux x86_64 引擎，20 个逻辑 CPU、约 15.3 GiB 引擎内存。测试使用独立部署 `agent-v1-test`、独立空控制卷、新账号与专属工作卷，HTTPS 入口 `https://127.0.0.1:18443`，宿主执行器接口绑定 `127.0.0.1:14093`。现有 `14090` 部署与原 A/B 数据未迁移、未替换。

测试配置有两个普通账号名额；正式配置默认四个。每账号 Agent、网关、出口共三个容器，使用既定 2 CPU/2048 MiB、0.5 CPU/512 MiB、0.5 CPU/128 MiB 配额。管理员账号没有助手容器。

HTTPS 使用只为本次合成验收生成的本地证书。Python 校验证书链与主机名；独立浏览器测试配置接受该自签证书，未修改操作系统信任库。实际服务器需提供客户机信任的证书。

## 浏览器与可用性

41 项独立浏览器检查通过，覆盖三角色 × 1366/1920/390 像素的 9 组布局，以及超级管理员连接表单的 3 组布局。普通用户直接看到输入框和五个个人入口，管理员仅加载用户、模型、操作记录，超级管理员显示完整管理入口。

已检查中文多行草稿切页保留、弹窗键盘焦点和 Escape、同一账号两个独立浏览器上下文读取同一会话。禁用缓存并限制浏览器仅访问本地 HTTPS 源后，所有页面资源可加载，没有外部资源请求。稳定页面三个角色均无浏览器控制台错误。

## 备份、恢复与交付

恢复演练已通过。先暂停两个合成账号并停止执行器与控制入口，生成包含 **7 个持久卷及宿主发布目录／匹配密钥** 的完整备份。逐文件摘要与主密钥解密匹配检查通过；运行中的执行器会阻止备份，现存资源会阻止恢复，均已实测。

在校验备份后，仅移除本轮合成源环境的容器、网络和六个账号卷，保留源控制卷、宿主目录及完整备份。随后恢复到新的 `agent-v1-restored` 部署标识与空宿主目录，全部卷重新创建并验证摘要，账号以暂停状态恢复，旧认证被撤销。

重新启动并逐个恢复账号后，**16 项比对通过**：两个账号仍可使用原密码登录，账号 ID 保留；合计 6 个会话及其消息摘要、1 个上传文件的完整内容摘要、个人 Skill、插件参数／版本和模型授权均一致；旧 Python 令牌失效，两个账号的插件连接测试恢复正常。

恢复后的测试入口继续使用 `https://127.0.0.1:18443`。原 `14090` 控制台检查仍为健康、版本 1.1.0／schema 2，原 A/B 六个容器均保持健康。本轮没有升级或接管原部署。

Linux Python 离线依赖已经下载为 Linux／通用 wheel，并在 `--network none` 的全新 Python 3.12 容器中使用 `--no-index --find-links` 安装成功。四镜像归档已经实际通过 `docker load` 导入检查。离线安装包包含四个固定版本镜像、宿主依赖、部署脚本、配置模板、API、插件示例、使用与开发手册；原始账号、密钥、数据库、运行目录、备份均排除。

本机保留脱敏明细于 Git 忽略的 `deploy/peixian/output/`：`platform-acceptance.json`、`platform-relay-acceptance.json`、`platform-model-acceptance.json`、`platform-compatibility-acceptance.json`、`platform-recovery-acceptance.json`，以及 `playwright/platform-browser-report.json` 和合成截图。复验脚本保存在源码中；它们只针对明确的合成测试部署，不应直接对生产数据执行。
