## 阅读路线与入口

本机统一入口：[打开沛县研判工作台](http://127.0.0.1:14090/)。超级管理员、管理员和普通用户使用同一个登录页，系统根据服务端角色与能力显示功能。

| 你要做什么 | 建议阅读顺序 |
| --- | --- |
| 第一次使用、上传资料并提问 | 快速开始 → 普通用户操作 → 完整练习 |
| 管理普通用户与模型 | 三角色管理 → 管理员流程 → 常见问题 |
| 创建管理员、维护空间、发布和授权插件 | 三角色管理 → 超级管理员专属操作 → 常见问题 |
| 安装自己的技能和已授权插件 | 普通用户操作中的技能、业务插件部分 |
| 使用 Python 调用 | Python/API 部分；先在个人设置创建程序访问令牌 |
| 重启电脑后恢复服务、迁移服务器 | 日常运维 → 链接的部署和迁移说明 |

网页中名称为“业务插件”的入口是获授权插件的管理页。当前交付包含合成连通性插件，用于验证发布、授权、安装、配置、调用和回退。真实业务数据插件、数据库接口及业务工作流仍需后续开发。

`127.0.0.1` 指当前正在使用的电脑。在另一台电脑输入这一地址，不会自动连接部署服务器。当前端口只监听部署电脑的回环地址；跨电脑访问由运维人员提供正式入口或 SSH 隧道，见“日常运维”。

旧版 `14091/14092` 是迁移前的 OpenCode 独立入口，当前账号控制台统一使用 `14090`。普通用户不需要添加项目、选择服务器目录或配置模型供应商。

### 三种角色各看哪些页面

| 角色 | 标识 | 主导航与管理范围 |
| --- | --- | --- |
| 超级管理员 | `super_admin` | 管理中心、个人设置；用户管理、模型管理、插件发布、技能模板、操作记录，另可查看空间任务和维护普通用户空间 |
| 管理员 | `admin` | 管理中心、个人设置；仅用户管理、模型管理、操作记录 |
| 普通用户 | `user` | 智能对话、我的文件、分析技能、业务插件、个人设置 |

管理角色不分配个人业务运行环境，不占用普通用户空间名额；需要处理业务资料时使用另行分配的普通用户账号，不能通过管理令牌冒用其他账号。

### 账号和数据属于谁

- 同一账号在不同浏览器或电脑登录，访问的是同一份会话、上传文件、技能和个人插件配置。
- 不同普通用户账号使用各自独立的运行环境和存储；一个用户安装插件不会自动给其他用户安装。两个管理角色没有业务运行环境。
- 公共插件目录共享的是超级管理员发布的代码版本，公共技能模板共享的是模板文本；个人配置、凭据和技能副本各自保存。
- 超级管理员负责账号、环境和资源授权。当前管理界面不提供浏览普通用户会话正文或文件内容的入口。
- 平台按账号隔离，不把账号绑定到物理电脑。需要不同人的数据分开时，应分配不同账号。

### 已有账号与密码

旧部署账号包含 `admin` 和业务用户 `client-a`、`client-b`。三角色升级将旧管理员一次性迁为超级管理员，账号名、UID 和密码保持，被迁移旧管理员的登录状态与令牌撤销；实际完成情况以迁移记录为准。新建角色为 admin 的账号是受限管理员，不等同于账号名叫 admin 的初始化超级管理员。历史验收账号不应作为日常共享账号使用。手册不记录任何密码、模型密钥或程序令牌。

首次密码由管理员交付。用户在页面修改密码后，原初始化密码文件不会自动同步成为新密码的备份。忘记普通用户密码时，联系管理员执行“重置密码”；管理员本人无法登录时，联系部署维护人员按受控恢复流程处理，不要重跑初始化来尝试覆盖现有账号。

## 快速开始：第一次完成对话

### 管理人员先准备

1. 使用管理员账号登录工作台；若提示首次修改密码，先完成改密，进入工作台。
2. 在“管理中心”准备一个可用模型连接，确认名称和实际模型 ID 正确。
3. 在“用户管理”创建普通账号，或者找到已有 `client-a`，通过“授权”分配模型。
4. 如需插件，由超级管理员发布后单独给该账号授权，再由用户配置启用。管理员不能发布插件或修改插件授权；其保存模型授权不得清空既有插件权限。
5. 等待账号环境显示“已就绪”。创建或配置保存返回成功，只表示请求已经保存；环境可能仍在准备或更新。
6. 将入口、账号和首次密码交给使用者。普通用户不需要知道模型地址、运行目录或容器名称。

### 普通用户开始

1. 打开工作台并登录。首次登录按页面提示修改密码，点击“保存并进入工作台”。当前浏览器会话继续可用。
2. 默认进入对话首页。确认顶部个人空间可用；只有一个模型时直接使用显示的模型，多模型时选择本次使用的模型。
3. 在输入框填写一个简短问题，例如：`请说明你可以怎样帮助整理一份普通表格，并先列出需要我提供的资料。`
4. 点击发送。回复会逐步显示；需要结束本次生成时点击停止。
5. 要分析文件，先在“我的文件”上传文件并等待解析完成，再回到对话中选择该文件后发送问题。
6. 要使用技能，先创建或复制技能并等待配置生效，再在对话中选择；要使用插件，先在“业务插件”安装并配置，再在问题中说明需要使用该能力。

首次验证请使用合成资料。发送问题会调用管理员配置的模型服务；如果配置的是 DeepSeek 官方 API，调用会使用该连接的 API 额度。模型服务停用、不可达、授权缺失或余额不足时，页面可正常打开但无法完成模型回答。

### 区分三种成功

| 看到的提示 | 它说明什么 | 下一步检查 |
| --- | --- | --- |
| 授权已保存、技能已保存、插件配置已保存 | 控制层已保存设置并安排应用 | 等待个人空间恢复就绪，查看生效状态 |
| 技能生效检查通过、插件连接测试通过 | 技能已被加载，或插件实现的测试入口返回成功 | 再用合成问题检查实际输出是否符合要求 |
| 回复生成结束且会话回到空闲 | 本次生成流程已结束，也可能是中止或失败 | 先检查错误提示，再核对来源、计算和工具结果；部分正文不代表完成 |

## 普通用户：对话、文件、技能与插件

### 一、登录、首次改密与页面导航

#### 1. 登录工作台

1. 打开管理员提供的工作台网址。
2. 在登录页填写“账号”和“密码”，点击“登录”。使用管理员分配给自己的普通用户账号。
3. 若进入“设置你的登录密码”页面，依次填写“当前密码”“新密码”“确认新密码”，点击“保存并进入工作台”。首次改密完成后，才能进入业务页面。
4. 若提示账号或密码不正确，先检查账号、输入法和大小写。忘记密码时联系管理员重置；当前页面没有自助注册或找回密码入口。

新密码须为 **12～256 个字符**，两次输入必须一致。当前浏览器登录有效期为 8 小时，到期后需要重新登录。

工作空间归属于账号：同一账号在不同电脑登录，访问的是同一份个人数据；不同账号分别拥有自己的对话、文件、技能和插件配置。因此，需要独立数据的人员应使用不同账号。

#### 2. 认识五个业务入口

| 入口 | 可以完成的操作 |
| --- | --- |
| 智能对话 | 选择授权模型、关联资料和技能、提问、停止生成、查看历史 |
| 我的文件 | 上传资料、查看解析状态和来源、下载原文件及分析成果 |
| 分析技能 | 编写个人分析步骤、导入文本、复制推荐模板、检查是否生效 |
| 业务插件 | 安装超级管理员授权的插件，配置、测试、启停和切换可用版本 |
| 个人设置 | 查看用户管理状态、修改密码、管理程序访问令牌 |

普通用户页面没有模型服务地址、模型密钥、终端、Git、项目目录或管理员配置入口。在手机或窄窗口中，点击左上角导航按钮（“打开导航”）展开菜单；对话历史可通过“显示对话记录”按钮打开。

#### 3. 先确认个人空间状态

空间状态可在账号区域或“个人设置”的“账号信息”中查看。

| 状态文字 | 用户应如何操作 |
| --- | --- |
| 已就绪、运行中 | 可以开始业务操作 |
| 等待处理、准备中 | 账号环境正在排队或开通，稍后再使用；持续不变时联系管理员 |
| 更新中 | 配置正在应用，等待完成后再发送新消息或保存配置 |
| 已暂停 | 联系超级管理员恢复空间 |
| 处理失败、异常 | 记录页面提示并联系管理员处理 |

保存、启停、回退技能或插件后，通常会出现配置更新过程。页面显示“个人工作空间正在更新配置，当前对话可继续查看或停止，完成后即可发送新消息。”时，可以继续查看当前对话、停止正在生成的回答，但要等待更新结束后再发新问题。不要反复点击保存制造重复更新。

### 二、智能对话

#### 1. 新建对话与选择模型

1. 点击左侧“智能对话”。
2. 点击对话记录区域的“新建对话”。新建动作会清空当前输入草稿，以及已选择的文件和技能；第一条消息发送后才形成实际历史记录。
3. 查看对话上方的模型名称。只有一个授权模型时，这里直接显示名称，无需切换；有多个授权模型时，在模型选择框中选择本次使用的模型。
4. 若显示“暂无可用模型”，请联系管理员为当前账号授权可用模型。此时不能发送消息，也不能通过按回车绕过。

欢迎页的“梳理关键事实”会填入示例问题，“使用分析技能”“结合已有资料”会打开相应选择界面；选择后仍需确认自己的问题并发送。

#### 2. 关联文件

1. 先到“我的文件”上传资料，等解析状态变为“已就绪”。上传步骤见下一章。
2. 回到“智能对话”，点击输入区下方的“关联文件”。
3. 勾选本次需要使用的资料，最多选择 **5 个文件**，点击“完成选择”。
4. 检查输入框上方的文件标签。点击已选标签可移除该文件。
5. 在问题中写明资料范围和输出要求，例如：“请根据已关联的合成事件记录整理时间顺序，列出原文依据，对缺少的信息标注待核实。”

“部分解析 · 请拆分重传”的文件不能勾选。可以先到文件页预览已提取范围，再拆分原文件并重新上传。上传成功、可以下载，与能够完整关联进一次对话，是不同的状态。

#### 3. 选择分析技能

1. 点击输入区下方的“使用技能”。
2. 在“使用分析技能”对话框中选择已启用的个人技能，最多 **5 个技能**。
3. 点击“完成选择”，检查输入框上方的技能标签。不需要的技能可点击标签移除。
4. 写清本次目标。技能提供处理步骤与输出要求，具体分析仍需要模型执行，并需要用户核验结果。

技能列表没有目标技能时，先在“分析技能”中创建或复制模板、启用并等待配置生效。启用代表该技能可用，不代表每一条提问都会自动按它完成。

**文件和技能的选择在一次发送后仍会保留。** 继续下一问前请检查标签，避免把上一次的资料范围带入新问题。点击“新建对话”会清空这些选择。

#### 4. 输入、发送、等待与停止

1. 在输入框描述问题，尽量写清“依据哪些资料、要分析什么、需要什么格式”。
2. 点击“发送”，或按 Enter 发送；按 Shift+Enter 换行。
3. 发送后，回答会逐步显示。正在处理时可看到简短进度，不需要连续重复发送同一问题。
4. 若不再需要继续生成，点击“停止生成”，或进度区中的“停止”。已经收到的文字会保留，停止不会删除对话。
5. 生成结束后，可在同一对话中继续追问。更换业务主题或资料范围时，建议新建对话。

输入框最多允许 32,000 个字符，但这不等于一次请求能携带这么多内容。服务端还会检查问题、技能正文、文件引用的合计大小；选择大量资料时，应先缩小分析范围。具体限额见文末“操作限制”。

在同一次打开的工作台页面内，切换到文件、技能等页面再返回，未发送的对话草稿会保留。草稿不是已保存的历史消息；刷新页面、退出登录或点击“新建对话”后不要依赖草稿仍然存在，重要长文请先自行保存。

#### 5. 处理补充问题与操作确认

当助手需要用户补充信息时，当前对话会显示“需要补充信息”。

1. 阅读每个问题，选择对应选项。标有“可以选择多项”的问题允许多选。
2. 若提供“自行填写”，可输入补充说明；当前自填框最多 1,600 个字符。
3. 完成所有问题后，点击“提交回答”。
4. 若不准备继续该请求，点击“暂不回答”。这个按钮会取消这项待答请求，不是将填写内容保存为稍后回答。

当出现“请确认本次操作”时，先阅读业务说明，再点击“仅允许本次”或“拒绝”。允许只针对当前请求；界面没有“以后全部允许”的选项。回答停留较久时，应先检查是否正在等待这里的用户操作。

#### 6. 查看业务处理详情

回答中的“读取文件”“使用技能”“调用已启用的插件”“保存结果”等处理条目可展开查看状态。插件详情仅展示管理员批准的业务字段，例如“输入条件”“处理结果”，不会显示完整内部协议或连接密钥。

判断某次操作是否实际执行，应结合条目的完成状态与返回结果，不应仅凭助手正文中的一句“已经处理”。文字结论也需与资料原文、来源位置核对。

#### 7. 管理历史记录

- **打开历史**：在“对话记录”中点击标题；用“搜索对话”按标题查找。
- **重命名**：点击对应记录的“重命名对话”图标，在“对话名称”中填写名称，点击“保存名称”。界面名称长度上限为 100 个字符。
- **删除**：点击“删除对话”图标，并确认“确定删除这条对话及其消息吗？”。当前页面没有回收站或恢复删除的入口，删除前先保留需要的内容。

### 三、我的文件：资料上传、解析与成果下载

#### 1. 上传资料

1. 点击“我的文件”，进入“资料文件”页签。
2. 点击“上传文件”或“选择文件”，也可将文件拖到“拖拽文件到这里，或点击上传”区域。
3. 可以一次选择多个文件，页面逐个上传；某一个文件失败时，之前成功上传的文件仍然保留，不要整批重复上传。
4. 等待列表中的解析状态更新。只有“已就绪”的文件才能在对话中正常关联。

当前支持 `.xlsx`、`.pdf`、`.docx`、`.txt`、`.md`、`.csv`。当前单个文件上限为 **20 MiB**，每账号原始上传文件总配额为 **1 GiB**。这两个限额分别对应单文件与个人资料总量。

旧格式 `.xls`、`.doc` 需要先另存为支持的格式；直接修改扩展名不能转换文件内容。当前页面没有“重新解析”或“重命名文件”按钮，解析失败时应修复原文件后重新上传。

#### 2. 理解解析范围

| 资料类型 | 当前提取方式与使用建议 |
| --- | --- |
| PDF | 提取文档已有文字，并保留页码；没有 OCR，扫描图片式 PDF 需先完成文字识别再上传 |
| XLSX | 提取工作表中的单元格值，保留工作表与行位置；使用已缓存的公式结果，不运行公式、宏或外部数据刷新。公式结果缺失时，先在 Excel 中重新计算并保存 |
| DOCX | 提取正文段落和表格，保留段落、表格与行位置；不能据此承诺完整识别图片、文本框、页眉页脚或原始排版 |
| TXT、MD | 提取文本，建议使用 UTF-8 编码；Markdown 按文字资料参与分析 |
| CSV | 按文本分隔的数据行提取，并保留行位置；复杂工作簿请使用 XLSX |

该功能提取文字和表格内容，不会在服务器启动 Office 执行宏，也不会自动读取文件引用的外部网页。原文中的图片或布局信息可能需要用户另行核验。

#### 3. 根据状态决定下一步

| 页面状态 | 含义 | 建议操作 |
| --- | --- | --- |
| 等待处理 | 已提交，等待解析 | 稍后查看，不必重复上传 |
| 解析中 | 正在提取内容 | 等待完成；处理中暂不能删除时，结束后再操作 |
| 已就绪 | 已提取可用文字 | 先预览核对，再到对话中关联 |
| 部分可用 | 只完成部分提取 | 可预览范围；拆分后重新上传，不能直接关联此文件 |
| 未识别到文字 | 未提取出可用文字 | 检查是否扫描件、图片或无文字文件，先转换或识别文字 |
| 暂不支持 | 文件类型不受支持 | 转换为支持的格式再上传 |
| 处理失败 | 解析过程中发生错误 | 依据错误提示修复或拆分原文件后重新上传 |

解析过程默认有 60 秒处理时限；过大的展开内容、过多片段或复杂结构也可能触发资源限制。能上传 20 MiB 文件，不意味着任意复杂文档都能在限制内解析完成。

#### 4. 预览与核对来源

1. 在“资料文件”中使用“搜索文件名称”定位文件，点击该行的“预览”。
2. 在“解析内容预览 · 请结合原文件核验”窗口中，按来源分块查看提取结果。
3. PDF 显示“第 N 页”；XLSX 显示工作表和行号；DOCX 显示段落或表格行；文本资料可能显示行范围。
4. 若有“仅预览部分内容，请下载原文件。”，点击“下载原文件”核对完整原件。
5. 关闭预览，回到对话中选择需要的资料。

预览窗口最多展示约 20,000 个字符、100 个片段。**预览窗口截断与文件状态“部分可用”不同**：前者可能只是显示范围有限，后者表示解析内容本身不完整。即使文件已就绪，关联进对话时仍会受到单次引用预算限制。

#### 5. 下载与删除原文件

- 点击资料文件行的“下载”即可下载原件；预览窗口中也有“下载原文件”。
- 点击垃圾桶按钮，阅读“确定删除这个文件吗？已有对话中的引用可能无法再次使用。”后再确认。
- 当前没有文件回收站。需要保留原件时应先下载，删除后历史消息可能仍显示此前文字，但不能据此认为原始附件还在。
- 个人原始资料配额不足时，可整理并删除已经备份、不再需要的文件，再上传新的资料。

#### 6. 下载分析成果

1. 在“我的文件”切换到“分析成果”。
2. 用文件名搜索或浏览列表，点击目标成果的“下载”。
3. 下载后打开检查内容、格式与本次任务是否一致。

“分析成果”展示助手实际生成并保存的结果文件。普通聊天文字不会自动变成可下载文件；如果需要文件，可在提问时明确要求生成可下载的结果，并结合“保存结果”的执行状态和成果列表核验。是否能够生成特定格式，取决于当前能力与实际执行结果，页面本身不保证任意格式转换。

当前成果页提供下载，没有资料页那样的预览、删除按钮。

### 四、分析技能：把常用步骤保存为个人方法

个人技能是一段可复用的文字说明，用于约定处理步骤、关注点与输出格式。它不会因为写了“访问某个数据源”就自动获得数据权限；外部业务访问仍取决于超级管理员授权且用户已启用的插件。

#### 1. 创建技能

1. 点击“分析技能”，在“我的技能”中点击“创建技能”；列表为空时也可点击“创建第一个技能”。
2. 填写“技能名称”，建议简洁区分用途。名称最多 60 个字符，不能包含斜杠、反斜杠或换行，也不能与自己的已有技能重名。
3. 填写“简短说明”，界面最多 240 个字符，用一句话说明用途。
4. 在“技能内容”中填写步骤和输出要求，内容不能为空，最多 32,000 个字符。可使用 Markdown；点击“预览”检查显示，点击“编辑”继续修改。
5. 根据需要打开“保存后启用”。
6. 点击“保存技能”，看到保存提示后等待工作空间完成配置更新。
7. 更新完成后点击该技能卡片的“测试”，确认是否已加载，再到对话中选择使用。

可用以下合成示例作为编写起点：

```markdown
## 适用场景
整理用户提供的合成事件记录。

## 分析步骤
1. 提取日期、参与对象和事项，保留原文出处。
2. 按时间顺序整理，区分明确事实与待核实信息。
3. 对缺失内容明确写“资料未提供”，不要补写事实。

## 输出要求
先给出事件时间线，再列出需要用户补充的问题。
```

技能内容也计入一次对话的引用预算。优先保存简洁、明确的流程，不要把大量原始资料全文塞入技能。

#### 2. 从文本导入

1. 点击“导入文本”，选择本机 `.md` 或 `.txt` 文件。导入文件上限为 512 KiB（界面提示为 512 KB）。
2. 系统以去掉扩展名的文件名预填技能名称，以文件全文预填技能内容，并打开编辑窗口。
3. 检查名称是否过长或重名、正文是否超出 32,000 个字符；必要时删减。
4. 核对“保存后启用”，点击“保存技能”。仅选择文件不等于已经保存或启用。
5. 等待配置应用后进行“测试”。

这里导入的是技能文字，不是插件代码包。即使导入文件小于 512 KiB，也仍需满足编辑框的名称与正文长度要求。

#### 3. 使用推荐模板

1. 切换到“推荐模板”页签，阅读模板名称和说明。
2. 对合适的模板点击“添加到我的技能”。
3. 回到“我的技能”找到新复制的技能；复制操作会创建个人副本并启用，重名时系统会自动调整副本名称。
4. 点击“编辑”，按自己的任务修改内容并保存，等待配置生效。

模板副本由当前用户维护。超级管理员以后修改模板，不会自动覆盖已经复制到个人技能中的内容。

#### 4. 启停、测试、回到上一个版本与删除

| 操作 | 具体做法 | 实际效果 |
| --- | --- | --- |
| 编辑 | 点击“编辑”，修改后“保存技能” | 保存新的内容，并触发空间配置更新 |
| 启用或停用 | 点击卡片“已启用／已停用”开关 | 决定技能是否可用于后续任务，需等待配置生效 |
| 测试 | 点击卡片“测试” | 打开“技能生效检查”，只检查技能是否已加载，不调用模型进行分析生成 |
| 恢复上一状态 | 点击圆形回退箭头，提示为“回到上一个版本” | 恢复上一份保存的名称、说明、内容和启停状态，并重新应用 |
| 删除 | 点击垃圾桶，确认“确定删除这个个人技能吗？” | 删除技能及其历史，当前无删除恢复入口 |

“技能已加载，可在新对话中选择使用”表示生效检查通过，不代表分析效果已经验证。“技能尚未生效，请等待配置应用完成”时先等待；状态长时间不变再联系管理员。

技能最多保存最近 20 份历史快照。编辑和启停都会形成保存记录，因此“回到上一个版本”不一定是上一段不同的正文，也可能是上一次开关状态。页面没有任意历史版本选择器；删除技能前如需保留内容，应先复制文本到自己的文件。

工作空间更新中时，保存、启停、复制模板、测试和回退等操作会受限。等待恢复就绪后继续。

### 五、业务插件：安装授权能力并应用配置

业务插件目录来自超级管理员发布与账号授权。**超级管理员发布插件**和**为某个账号保存插件授权**是两个步骤；普通用户只能看到授予当前账号、且仍有可用发布版本的插件。

普通用户不在本页上传 ZIP 或编写服务代码，也不用填写原始 JSON 配置。界面按插件版本提供的表单显示可配置项。

#### 1. 首次安装

1. 点击“业务插件”，确认已登录的是自己的目标账号。
2. 在目录中找到目标插件，阅读名称、用途和版本。未安装的卡片显示“可安装”，点击“安装插件”。
3. 在“安装 · 插件名称”窗口中选择“插件版本”。
4. 按表单填写配置。带星号的项目是必填项；具体业务字段、凭据要求由插件定义。
5. 若提示“这个插件无需额外配置，安装后即可启用。”，无需添加其他参数。
6. 保持“应用后启用”开启，点击“保存并应用”。
7. 等待个人空间完成配置更新，再执行“连接测试”。

目录没有目标插件时，不要先尝试重装软件。请管理员确认：是否发布了启用中的版本、是否在当前账号的“授权”窗口勾选了该插件、是否点击“保存授权”。管理员保存授权后，可切换到其他页面再返回“业务插件”，或刷新浏览器。只在当前页面等待，并不保证马上重新读取目录。

#### 2. 填写和修改配置

已安装插件点击“配置”，进入“配置 · 插件名称”窗口。

- 普通字段按用途填写文字、数字、开关或下拉选项。
- 分组字段在对应分组中填写；列表字段通过“添加一项”“删除”维护。
- 密码或密钥类字段会遮蔽输入。已有凭据不会原文回显；留空会保留已经保存的凭据，输入新值才会替换。不要将“留空”当成清除已保存凭据的操作。
- 若出现“此版本表单不支持，请联系管理员。”，需由管理员修正发布版本的配置描述；普通用户不能在这里切换为原始 JSON 编辑。
- 修改后点击“保存并应用”，等待生效后再使用或测试。

表单字段应来自插件的实际说明。无法确定业务参数时，请向管理员或插件提供方确认，不要把其他账号的凭据复制过来尝试。

#### 3. 连接测试

1. 确认插件已安装、已启用，个人空间状态已就绪。
2. 点击插件卡片的“连接测试”。
3. 在“插件测试结果”中阅读实际结果，点击“关闭”返回。

“配置已保存，等待运行环境应用”表示尚未完成生效，应等待后再测试。连接测试调用插件自身提供的测试能力；若该版本没有提供测试能力，页面会明确说明不支持。不能把“不支持测试”当作连接成功。

连接测试成功仅说明该插件定义的检查通过，不代表所有业务查询条件或整套分析流程都成功。正式使用时仍要核对本次插件调用的返回结果。

#### 4. 启用、停用和对话中使用

1. 点击卡片的“已启用／已停用”开关调整状态。
2. 等待空间配置应用完成。
3. 回到“智能对话”，用业务语言描述希望进行的操作，并补充必要条件。
4. 观察“调用已启用的插件”等业务处理条目，展开核对执行状态和允许展示的输入、输出信息。

页面没有逐条消息选择插件的专用下拉框；当前已授权、安装并启用的插件作为可用能力提供给助手。安装并不意味着每条消息都会调用它。当前页面也没有“卸载插件”按钮，不再使用时可以停用。

#### 5. 升级或切换可用版本

1. 点击插件的“配置”。
2. 在“插件版本”中选择超级管理员发布的目标可用版本。
3. 逐项检查配置：共同字段会尽量保留，新字段可能采用默认值，已移除字段不再显示；新增必填项需要补齐。
4. 检查“应用后启用”，点击“保存并应用”。
5. 等待个人空间就绪，再做一次“连接测试”和必要的业务核验。

超级管理员发布新版本，不会自动把当前已安装的可用旧版本升级。若已安装版本被管理员停用，卡片会显示“版本已停用”，并提示在配置中选择可用版本；若已无可用版本，请联系管理员。

#### 6. 回到上一次安装状态

1. 在插件卡片点击圆形回退箭头，提示为“回到上一个版本”。
2. 等待配置更新完成。
3. 检查版本、启停状态和配置，再进行连接测试。

插件的回退对象是**上一次保存的安装状态**，包括版本、配置和启停状态。因此，它可能只是撤销上一次改配置或开关，并不一定切换到更早的版本号。当前仅保留一份可回退状态，没有任意历史版本列表；执行回退后不能无限连续回退。

回退目标版本还必须存在且处于允许使用的状态。若管理员已停用或收回该版本，回退可能被拒绝，应选择当前允许的版本或联系管理员。

### 六、个人设置、程序访问与外观

#### 1. 查看账号信息

点击“个人设置”，在“账号信息”中查看账号、角色和空间状态。普通用户不能在这里修改角色或给自己增加模型、插件授权。

#### 2. 修改密码

1. 在“修改登录密码”中填写“当前密码”“新密码”“确认新密码”。
2. 确认新密码为 12～256 个字符，点击“更新密码”。
3. 保存成功后，当前浏览器会话继续可用。

**修改密码会使该账号其他已登录浏览器会话和已有程序访问令牌失效。** 若个人 Python 程序随后提示登录失效，需要重新创建令牌并更新程序配置。首次改密也适用同样的凭据更新规则。

#### 3. 创建程序访问令牌

仅在需要由自己的 Python 程序等客户端访问时使用。日常在浏览器中操作不需要创建令牌。

1. 在“程序访问令牌”区域点击“创建令牌”。
2. 在“令牌名称”中填写便于识别的名称，例如“个人 Python 客户端”，最多 80 个字符。
3. 点击“创建令牌”。
4. 在“保存你的访问令牌”窗口点击“复制令牌”，把完整令牌保存到程序的私密配置位置。
5. 确认保存后点击“我已保存”。若浏览器不允许复制，可选中文字自行复制。

完整令牌只在创建成功时显示一次，关闭窗口后列表不会再次显示完整值。当前令牌有效期固定为 **30 天**，列表显示名称、创建时间和到期时间；界面没有自选有效期或逐项权限范围。令牌继承当前账号的业务访问权限，不会增加管理员权限。

程序调用使用 Bearer 令牌认证。不要把令牌粘贴到对话、截图、代码仓库或共享文档中，也不要把它当作普通用户名称。

#### 4. 撤销令牌

1. 在令牌列表找到不再使用的条目，点击“撤销”。
2. 确认“确定撤销此访问令牌吗？使用它的程序将无法继续连接。”。
3. 撤销后，使用旧令牌的程序需换用新令牌才能继续。撤销操作没有恢复按钮。

#### 5. 切换外观与退出登录

- 在左侧导航底部的账号区域点击外观图标，可在“切换深色”和“切换浅色”之间切换。它不在“个人设置”的表单中。
- 外观偏好保存在当前浏览器中；换电脑、换浏览器或清理浏览器数据后，不保证沿用之前选择。
- 使用结束后点击账号区域的“退出登录”图标。退出当前页面不会替你撤销个人设置中创建的程序访问令牌；不再使用的令牌应单独撤销。

### 七、操作限制与用户侧提示对照

#### 1. 当前主要限制

以下为当前实现值。容量或资源限制若在后续版本调整，以管理员更新的说明为准；普通用户页面没有调整这些限制的入口。上传限制、解析限制和一次模型请求的引用限制应分开理解。

| 项目 | 当前限制或行为 |
| --- | --- |
| 登录密码 | 12～256 个字符 |
| 浏览器登录有效期 | 8 小时，到期重新登录 |
| 程序访问令牌 | 固定 30 天；全文仅创建时显示一次 |
| 一次消息的文件选择 | 最多 5 个；部分解析文件不能关联 |
| 一次消息的技能选择 | 最多 5 个，须存在且启用 |
| 对话输入框 | 最多 32,000 个字符，仍受合计引用预算约束 |
| 一次消息中的资料引用 | 文件累计内容预算 24,000 个字符，来源标记也占用预算 |
| 问题＋技能正文＋文件引用 | 合计最多 18,000 个 UTF-8 字节；中文通常占多个字节，不能按 18,000 个汉字理解 |
| 单个资料文件 | 默认 20 MiB |
| 个人原始上传资料总量 | 默认 1 GiB；不等于整个工作空间磁盘的统一总上限 |
| 单次解析 | 默认 60 秒；另有内存、展开内容和片段数量限制 |
| 文件预览显示 | 最多约 20,000 个字符、100 个片段，超出时提示下载原件 |
| 技能编辑 | 名称 60 字符；简短说明 240 字符；正文 32,000 字符 |
| 技能文本导入 | `.md`／`.txt`，最大 512 KiB，仍受编辑字段长度限制 |
| 技能回退 | 最近最多 20 份历史快照，按上一次保存状态回退 |
| 插件回退 | 一份上次保存的安装状态，目标版本须仍可用 |

若单次引用超限，优先缩短问题、减少关联技能、选取更少资料，或将文件按问题范围拆分后再上传。不要把单文件上传上限理解为一次可交给模型的上下文容量。

## 三角色管理：用户、模型、插件与模板

### 管理员先读：权限范围和常用流程

管理员（admin）管理**全部普通用户**，不局限于自己创建的账号。日常步骤：

1. 在“用户管理”创建普通用户，交付一次性初始密码；系统自动安排该用户空间开通。
2. 点击普通用户的“授权”，仅调整“授权模型”；管理员不能提交插件授权字段。
3. 使用“停用账号”“启用账号”和“重置密码”管理普通用户。停用会撤销登录并自动排队暂停空间，不删除资料。
4. 在“模型管理”维护现有模型连接、测试、默认与启停，为普通用户分配模型。模型变更可以触发后台配置应用。
5. 在“操作记录”查看只读脱敏管理记录。记录没有模型密钥、插件凭据、私有路径或业务全文。
6. 对已停用普通用户点击“启用账号”，服务端检查容量并自动排队恢复原空间。若暂停尚未完成或容量不足，返回冲突且账号保持停用，待条件满足后重试。独立暂停、恢复、重试空间或查看空间任务仍由超级管理员操作；已经启用但被手动暂停的空间不会因重复启用自动恢复。

管理员不能管理其他管理员或超级管理员，不能修改部门组织、用户部门归属和角色，不能管理平台插件或公共模板。后台自动开通、暂停和配置应用，不等于管理员获得独立环境维护权限。

### 超级管理员先读：新增管理员与专属能力

超级管理员（super_admin）拥有上述用户和模型管理能力，并负责插件、模板与独立空间维护。

创建管理员：在“用户管理”点击“创建账号”，将“账号角色”选为“管理员”，填写账号和初始密码，点击“创建管理员”。该表单不提供模型/插件授权，创建后没有业务空间或开通任务。超级管理员可启停或重置管理员密码；不支持将已有普通用户改成管理员，也不能通过该表单增建超级管理员。

现有技能模板只有超级管理员可管理。部门公共 Skill 的正式审核、发布、授权、下架也已确定唯一归超级管理员，但该完整流程仍在正式方案批次 D 实现。本次模板权限调整不能当作正式审核发布已经交付。普通用户的个人 Skill 和获授权插件个人配置继续保留。

### 1. 登录与管理入口

使用运维交付的超级管理员账号与当前密码登录“沛县 · 智能研判平台”。当前本机控制台入口为 http://127.0.0.1:14090；远程使用方式以运维交付为准，其他电脑的 127.0.0.1 不指向这台服务器。

全新安装的账号名为 admin、角色为 super_admin；升级后的旧账号保持原账号名和密码。密码以实际交付为准。首次登录若进入“设置你的登录密码”，填写“当前密码”“新密码”“确认新密码”，点击“保存并进入工作台”。服务端密码长度要求为 12～256 个字符；页面建议组合字母、数字与符号，当前没有额外的字符种类强制规则。

初次创建或被重置密码的普通账号，也必须完成首次改密，才能进入正常功能。登录失败过多会短暂限制尝试，按提示等待五分钟后再试。

超级管理员进入“管理中心”，有五个页签；管理员只显示用户管理、模型管理、操作记录。

| 页签 | 用途 |
| --- | --- |
| 用户管理 | 创建普通账号、授权模型和插件、重置密码、暂停恢复空间、停用启用账号 |
| 模型管理 | 配置模型名称、接口、真实模型 ID、密钥与可用状态 |
| 插件发布 | 上传插件 ZIP，管理各版本的可用状态 |
| 技能模板 | 发布、修改、删除供用户复制的技能指令 |
| 操作记录 | 查看近期管理操作的时间、操作者和目标 |

超级管理员用于管理平台；当前管理页面没有代替用户登录、浏览用户私有会话和文件或读取用户插件凭据明文的功能。只有超级管理员能创建普通用户和管理员；不能通过创建表单新增超级管理员，也没有角色升降级、账号改名、永久删除或批量导入入口。所有超级管理员行不提供普通账号管理操作，其自身密码通过个人设置修改。

### 2. 创建账号并开通空间（以下流程针对普通用户）

#### 2.1 创建顺序

建议先在“模型管理”配置并启用至少一个模型，再创建业务账号。插件可按需预先发布，也可以暂不授权。没有获授权的可用模型时，空间可以开通，但用户不能完成模型对话。

1. 进入“用户管理”，点击“创建账号”。超级管理员在“账号角色”选择“普通用户”；管理员不显示角色选择，只能创建普通用户。
2. 在“创建账号”填写“账号”。实际规则为：
   - 3～40 个字符，首字符是英文字母或数字。
   - 其余允许英文字母、数字、下划线、点或连字符。
   - 不能与已有账号重复，创建后该表单不提供改名。
3. 填写“初始密码”，或留空由系统生成。手动填写遵守 12～256 字符的长度规则。
4. 在“授权模型”勾选允许该用户使用的模型。
5. 超级管理员可在“授权插件”勾选插件。管理员只显示“授权模型”，不能查看或修改插件授权字段。
6. 点击“创建并开通”。
7. 在“保存初始密码 · 账号名”弹窗点击“复制密码”，妥善交付给本人，再点击“我已保存”。

完整密码只在本次结果弹窗中展示，无论它是手动填写还是系统生成。关闭后没有查看旧密码的入口；遗失时使用“重置密码”。

#### 2.2 判断开通结果

创建成功只表示账号、空间记录和任务已提交。真正的开通由宿主执行器异步完成。

在账号列表查看“空间状态”；超级管理员还能在下方“空间任务”查看进度，管理员需要时联系超级管理员查询任务。必要时点击右上方“刷新状态”。等待空间变成“已就绪”后，再通知用户开始使用。

| 状态 | 含义与处理 |
| --- | --- |
| 等待处理 | 已排队。持续不变时检查宿主执行器是否运行 |
| 准备中／启动中 | 正在准备运行环境，等待完成 |
| 更新中 | 正在应用模型、插件、技能等配置 |
| 已就绪 | 运行环境已通过就绪检查，可开展对应业务验证 |
| 已暂停 | 空间停止运行，账号和数据保留 |
| 处理失败 | 本次任务未完成，查看说明、处理原因后重试 |

“已就绪”不能代替每个外部模型或业务插件的真实功能验收。

#### 2.3 状态统计与配额

当前默认最多预留 4 个普通用户空间，管理角色不占用这些名额。只有超级管理员显示“运行中的空间”和“等待处理的任务”；运行数统计就绪或运行的空间，不等于服务端预留数。排队开通、更新或尚未确认停止的失败空间可能继续占用名额。

因此，运行计数不足 4 仍可能提示容量不足，应检查任务和预留空间，不能靠反复创建账号解决。“可见账号”按当前角色有权管理的范围显示，不能当作全平台运行空间数。

每个账号的 CPU、内存和网络配置由部署模板固定，页面没有单独调整的输入框。空间暂停后账号和数据仍然保留。宿主资源不足或执行器未运行，也会影响任务完成。

### 3. 修改授权与账号状态

#### 3.1 给已有账号授权

1. 在目标普通账号行点击“授权”。
2. 勾选需要新增或保留的模型；超级管理员还可调整插件授权，管理员不显示该字段。
3. 取消勾选表示撤销权限。
4. 点击“保存授权”，等待该账号的配置任务完成。

保存的是本次有权限编辑的完整授权列表，不是仅新增本次勾选项；管理员只提交模型授权，不影响旧插件授权。模型与插件必须在全局处于可用状态，账号授权不能绕过全局停用。

插件授权只表示用户可以选择这个插件；个人版本、参数与启用仍由用户在自己的插件页面配置。暂停空间保存授权后不会自动启动，需要时由超级管理员另行“恢复空间”。

#### 3.2 暂停、恢复、停用分别做什么

| 操作 | 登录与空间行为 |
| --- | --- |
| 暂停空间 | 账号仍可登录；排队停止空间，执行器确认停止后释放名额，数据保留 |
| 恢复空间 | 要求账号已启用且有可用名额，启动原空间并应用当前配置 |
| 重试 | 对失败空间重新尝试开通；不等于清空或重建用户数据 |
| 应用配置 | 运行空间排队更新；暂停空间保存待应用配置，不自动启动 |
| 停用账号 | 立即撤销该账号登录状态，同时排队暂停空间；实际停止仍是异步过程 |
| 启用账号 | 仅从停用变为启用时，原子检查/预留名额并排队恢复原空间；暂停未完成或容量不足则 409，账号仍停用 |

**恢复停用账号：点击“启用账号”，成功提交后等待空间“已就绪”；不需要额外点击“恢复空间”。** 若返回 409，先等待原暂停任务完成或请超级管理员释放运行名额，再重试启用。账号本来已启用、只是空间被超级管理员手动暂停时，只有超级管理员可独立“恢复空间”；重复启用或修改授权不会绕过这一限制。

忙碌空间的更新或停止可能等待当前任务结束，或由执行器延后处理。“操作已提交”不表示已经完成，不应连续点击制造重复任务。停用的登录撤销与后台停止空间是两个时间点，应回看任务确认结果。

#### 3.3 重置普通账号密码

1. 找到账号，点击“重置密码”。
2. 填写“新初始密码”，或留空由系统生成。
3. 点击“确认重置”。
4. 保存一次性密码弹窗中的新密码，交付本人。
5. 告知用户重新登录并完成改密。

重置后原登录状态失效，但不删除会话或文件，也不自动启用已停用账号。普通账号重置接口不能用于重置超级管理员自身密码；超级管理员自身密码修改使用账户设置的改密功能，初始化密码恢复归运维处理。

### 4. 模型管理（两种管理角色均可）

#### 4.1 添加与授权

进入“模型管理”点击“添加模型”，填写“添加授权模型”表单并“保存模型”。保存后在卡片点击“连接测试”，再到目标账号的“授权”中勾选该模型。

| 字段 | 填写说明 |
| --- | --- |
| 显示名称 | 用户看到的业务名称，例如“通用研判助手”，不要求等于上游模型 ID |
| 简短说明 | 适用场景说明，不要填写密钥或内部连接参数 |
| 兼容接口地址 | OpenAI 兼容接口根地址，通常以 /v1 结尾，例如 https://model.example/v1；不要填到 /chat/completions |
| 模型标识 | 推理服务实际提供的模型 ID，由接口文档或模型列表确认 |
| 访问密钥 | 接口需要认证时填写；编辑时留空保留已有值 |
| 允许使用 | 全局可用开关 |
| 设为默认模型 | 默认选择标记，不自动为所有账号授权 |

名称、接口地址、模型 ID 为必填，服务端各自上限为 500 个字符；说明最多保存 500 字符。接口地址接受 HTTP/HTTPS，但不能包含 URL 用户名密码、查询参数或片段。

本版本使用 OpenAI 兼容 Chat Completions 协议。仅提供其他专有协议的服务，不能只填网址就接入。实际服务还需支持所用的对话、流式与工具调用能力；当前页面不提供全部厂商专用参数、温度、上下文或推理模式调节。

#### 4.2 连接测试的准确含义

模型“连接测试”请求根地址后面的 /models，检查返回列表是否包含填写的模型 ID，不发送一轮模型对话。

- “连接成功，模型 ID 已确认”：本次地址、认证和模型列表查询通过。
- “未能确认模型，请检查地址、凭据和模型 ID”：核对根地址、凭据、模型标识和 /models 兼容性。
- 测试成功不代表真实对话、流式、工具调用、计费额度或业务效果均已验收。
- 有的服务支持对话却不提供标准 /models，此按钮也可能失败；应由接入人员核查，而不是凭此推断所有功能不可用。

#### 4.3 名称隐藏和默认模型

普通用户只收到自己获授权且可用的模型名称、说明和默认标记，不会收到接口地址、真实模型 ID 或密钥。超级管理员可编辑地址和模型 ID，但原密钥也不会回显，只有“访问凭据已配置”状态。

若需要隐藏厂商品牌，应选择业务化的“显示名称”和“简短说明”。超级管理员自己把品牌写在名称中，普通用户会看到它，平台不会自动改写名称。

默认标记不自动授予权限。账号只能使用自己获授权且可用的模型，没有可用授权时不会回退到未授权模型。

#### 4.4 编辑与停用

在卡片点“编辑配置”修改，已有授权账号将排队更新。变更共享地址、真实模型 ID 或密钥会影响这些账号，应检查各空间任务。

关闭“允许使用”用于全局停用模型。当前没有模型删除按钮，也没有查看或清空原密钥的按钮；编辑密钥留空表示保留，不表示删除。

### 5. 插件发布：发布、授权、配置、验收（超级管理员专属）

#### 5.1 完整链路

插件不是上传 ZIP 后自动分发给所有人的功能，使用链路为：

1. 超级管理员发布审核过的固定版本插件包。
2. 超级管理员给账号授权插件 ID。
3. 用户选择可用版本，填写自己的配置并启用。
4. 等待执行器应用到该账号空间。
5. 用户进行连接测试及实际工具调用验证。

同一插件的不同用户配置和凭据各自独立。普通用户不能上传任意可执行代码；超级管理员发布的插件也不会自动获得业务数据库或外网访问权限。

#### 5.2 ZIP 与 manifest 规范

推荐结构如下，manifest.json 必须在 ZIP 根目录：

~~~text
guide-marker-1.0.0.zip
├── manifest.json
└── entry.mjs
~~~

约束：

- ZIP 不超过 20 MiB，最多 1000 个条目，声明解压大小合计不超过 100 MiB。
- 不允许绝对路径、上级目录跳转、反斜杠路径、冒号、符号链接和重复文件名；也应避免仅大小写不同的同名文件。
- 入口是包内已经打包好的 .mjs 文件，无网 Agent 启动不负责自动下载 npm 依赖。
- 当前兼容 OpenCode 1.18.30。
- 同一插件 ID 和版本不可覆盖；修改后使用新版本号。

| manifest 字段 | 当前协议 |
| --- | --- |
| id | 小写字母开头，总长 1～64，其余为小写字母、数字或连字符；不能有下划线 |
| version | 三段数字，如 1.0.0；不加 v 前缀、beta 后缀 |
| name | 显示名称，省略使用 id，最多保存 100 字符 |
| description | 说明，最多保存 1000 字符 |
| opencode_version | 建议显式写 1.18.30 |
| entry | 包内 .mjs 相对路径，默认 entry.mjs |
| config_schema | 生成用户表单并校验参数的 JSON Schema |
| tools | 实际工具名称列表，应与入口返回的 tool 对象键一致 |
| display | 安全展示字段对象，包含 input_fields 和 output_fields |

上传时会检查结构、路径、表单和兼容声明，但不会执行插件证明业务功能正常。tools 写错或未正确列出，即使入口加载，工具也可能因未开放权限而无法使用。不要把 tools 当作开放 shell、PTY 或任意内置工具的入口。

当前展示协议是 display.input_fields 和 display.output_fields；早期合成例子的 display_fields 不是当前工具卡片使用的协议。

#### 5.3 配置表单能力与凭据

config_schema 支持明确结构的对象、文字、数字、整数、布尔、有限枚举及非凭据标量数组。每个对象必须列 properties，并关闭 additionalProperties。

~~~json
{
  "type": "object",
  "properties": {
    "organization": {
      "type": "string",
      "title": "单位名称"
    },
    "access_token": {
      "type": "string",
      "title": "业务接口凭据",
      "writeOnly": true,
      "format": "password"
    }
  },
  "required": ["organization", "access_token"],
  "additionalProperties": false
}
~~~

这只是字段规范示例，不代表平台已有对应业务接口。实际插件代码必须处理这些参数。

- title 是字段显示名称，required 列出必填字段。
- 每个对象最多 64 个属性，嵌套深度受限；不支持自由 JSON 对象、联合类型或 $ref。
- 数组只能是文字、数字、整数、布尔等非凭据标量，不支持对象数组和凭据数组。
- 敏感字段使用 writeOnly: true 或 format: "password"。保存后只显示是否配置，不回显原值。
- 更新已有配置时，凭据字段留空通常保留旧值，不代表清空。
- 提交时服务端按 Schema 校验，不能只靠浏览器绕过必填或格式要求。

#### 5.4 最小可理解插件示例

以下纯演示插件返回个人配置中的标记，不访问真实数据、不调用模型。它按已有合成验收插件的协议整理；作为文档示例提供，发布前仍需由插件维护者完成测试。

manifest.json：

~~~json
{
  "id": "guide-marker",
  "version": "1.0.0",
  "name": "演示标记插件",
  "description": "返回个人配置的演示标记，学习发布与授权流程",
  "opencode_version": "1.18.30",
  "entry": "entry.mjs",
  "tools": ["guide_marker"],
  "config_schema": {
    "type": "object",
    "properties": {
      "marker": {
        "type": "string",
        "title": "演示标记",
        "minLength": 1
      }
    },
    "required": ["marker"],
    "additionalProperties": false
  },
  "display": {
    "input_fields": [],
    "output_fields": ["marker", "version"]
  }
}
~~~

entry.mjs：

~~~javascript
export default async function (context, options) {
  return {
    tool: {
      guide_marker: {
        description:
          "Return the configured demonstration marker when asked to verify this plugin.",
        args: {},
        async execute() {
          return JSON.stringify({
            marker: options.marker,
            version: "1.0.0"
          });
        }
      }
    }
  };
}

export async function test(options) {
  return {
    ok: typeof options.marker === "string" && options.marker.length > 0,
    message: "Marker configuration checked"
  };
}
~~~

协议要点：

- 默认导出接收 context、options；后者是该用户保存的个人配置。
- 返回对象中的 tool.guide_marker 对应 manifest.tools 的 guide_marker。
- args: {} 表示演示工具无需额外输入；真实工具参数按 OpenCode 工具接口声明，不能把任意 manifest 字段当作工具入参协议。
- execute 返回 JSON 字符串，供安全展示提取选定的顶层业务字段。
- 独立的具名导出 test(options) 为“连接测试”入口，必须返回布尔 ok 和字符串 message。
- 此例 test 只检查标记是否填写，不声称做了网络验证；真实业务插件需要实现与实际用途相符的测试。

已有协议参考位于 deploy/peixian/console-acceptance.py 中的 1.2.0 合成插件示例。该脚本包含其他账号和验收操作，不能作为普通插件安装命令运行整个脚本。

#### 5.5 实际发布步骤

1. 开发人员准备 ZIP，并说明功能、版本、参数、必要业务权限和验收方法。
2. 超级管理员到“插件发布”点击“发布插件包”，选择 ZIP。
3. 发布成功后核对名称、版本和可用状态。
4. 到目标账号“授权”勾选该插件并保存。
5. 通知用户进入自己的插件页面，选择版本、填写参数并保存启用。
6. 在“空间任务”确认配置应用；出现“配置已保存，等待运行环境应用”时继续等候或排查执行器。
7. 用户执行插件连接测试，再以明确任务验证实际工具调用。

没有导出 test 的插件会提示不支持连接测试，不应被当作“已测试通过”。连接测试运行在有超时、资源限制的受控子进程中；自由文本 test.message 不原样回显，而被转成固定的通过、失败或不支持提示，避免泄露地址、凭据等信息。

连接测试通过与模型实际调用插件仍是两件事。是否调用工具受模型、提示词、工具说明和权限影响，并不是每条对话都会自动调用。

#### 5.6 版本、停用、回退与授权

| 场景 | 操作与结果 |
| --- | --- |
| 发布升级 | 保持 id，使用新 version；不会自动升级所有用户 |
| 用户升级 | 用户选择新版本，按新 Schema 填配置并保存，等待应用 |
| 全局停用版本 | 超级管理员关闭该版本可用性，受影响账号排队更新，用户不能再选择它 |
| 撤销单个用户权限 | 在账号授权中取消该插件，不影响其他获授权用户 |
| 个人回退 | 用户恢复此前一次保存的版本和配置；目标版本必须仍可用，用户必须仍获授权 |
| 重新启用版本 | 只恢复全局可用性，不能代替个人授权、配置和启用 |

当前没有覆盖旧版本或删除已发布版本的界面。插件授权按 ID，用户安装按具体版本；两者不要混淆。

#### 5.7 展示及业务接入边界

display 只显示选定的顶层文字、数字或布尔字段。输入和输出各最多处理 20 个字段；字段名以英文字母开头、最多 60 字符，允许字母、数字、下划线。密钥、密码、令牌、URL、路径、命令等敏感含义字段会被排除，字符串还受长度和敏感内容过滤。

因此，不应预期原始工具响应会完整出现在聊天卡片中。插件应提供短小明确的非敏感业务展示字段，避免把内部 URL、路径或长日志当成用户输出。

发布包不会自动接入数据库、任意外部网络或业务系统。当前空间采用受控网络与工具权限，真实接口连接需另行实现和配置。标记插件通过，只能证明该测试覆盖的加载、配置和调用流程，不能证明已接通真实业务数据。

### 6. 技能模板管理（超级管理员专属）

#### 6.1 模板、技能和插件的区别

技能模板是可复制的任务指令，约定工作步骤、证据要求和输出格式。插件提供可执行工具与配置。模板不会凭文字增加数据库访问权、网络权限或新工具。

超级管理员模板在公共目录中供普通用户复制，没有逐账号的模板授权选择框。用户复制后形成个人技能，后续自行编辑、启用和维护。

#### 6.2 创建模板

进入“技能模板”点击“创建模板”，填写：

| 字段 | 要求 |
| --- | --- |
| 模板名称 | 明确简短，最多保存 60 字符；避免斜杠、反斜杠和换行，便于复制后编辑 |
| 模板说明 | 适用场景，最多保存 500 字符 |
| 模板内容 | 完整指令，1～32000 字符 |

点击“保存模板”，通知用户复制。以下是文本结构示例：

~~~text
名称：材料事实与线索整理

适用范围：
仅使用用户提供的材料，以及当前账号已授权工具实际返回的资料。

步骤：
1. 确认材料范围、时间范围和用户目标。
2. 列出有来源依据的事实，保留必要的证据定位。
3. 区分已确认事实、待核实线索和推测。
4. 资料不足时说明缺口，不编造人员关系、记录或工具结果。
5. 只调用当前账号实际拥有的工具，缺少工具时说明限制。

输出：
一、资料范围
二、已确认事实与依据
三、待核实线索
四、需要补充的资料
~~~

本例不表示平台已经接入任何指定业务系统。

#### 6.3 编辑、删除与生效

- 编辑公共模板只更新目录，不会自动覆盖用户此前复制的个人技能。
- 删除时页面明确提示“用户已复制的个人技能会保留”。
- 当前模板页没有历史回退或强制推送到所有用户的按钮。
- 用户复制后，个人技能配置仍由空间任务应用。
- 技能“测试”确认运行环境已加载对应技能名称，不自动证明模型遵循了全部指令或业务质量合格。

### 7. 操作记录与排查未生效（两种管理角色均可读记录）

“空间任务”只有超级管理员可见，用于看开通、更新和停止是否完成，显示任务、账号、状态、提交时间和说明。接口最多获取最近 200 条，当前界面展示前 30 条。

“操作记录”允许两种管理角色只读查看。在“操作人”“操作类型”“执行结果”选择条件，点击“筛选”；点击“重置筛选”恢复全部条件。执行结果包括成功、已拒绝、失败。当前只显示权限范围内最近 500 条匹配记录，不包含业务正文和凭据；没有分页或导出按钮。操作人下拉使用当前角色可见账号，不能通过填写其他账号参数取得私有业务内容。

**记录“成功”表示该管理请求成功，不表示后续异步空间任务已经完成。** “已拒绝”和“失败”应结合动作、对象和时间判断；历史记录也不能替代本次运行验证。 必须结合空间状态和任务结果判断配置是否生效。审计不是用户业务全文查看页，也不是全部历史的无限导出功能。

| 现象 | 查看顺序 |
| --- | --- |
| 创建后长期等待 | 先看空间任务，再由运维检查执行器，不要重复创建替代账号 |
| 有空位仍容量不足 | 检查排队、更新和未确认停止的失败空间预留 |
| 用户看不到模型 | 全局可用、账号授权、空间应用状态 |
| 模型连接测试失败 | 根地址、凭据、真实模型 ID、/models 协议 |
| 插件发布了但用户看不到 | 是否授权该账号、是否存在可用版本 |
| 插件可见却不能调用 | 个人版本和配置、启用、应用状态、manifest.tools 与实际 tool 名称 |
| 插件测试不支持 | 是否导出 test(options)，是否有其他明确验收方法 |
| 插件测试通过却无数据 | 测试覆盖范围、实际业务接口、网络和账号权限 |
| 修改配置不立即生效 | 空间是否暂停或忙碌、配置任务是否完成 |
| 重新启用没有完成 | 检查是否返回 409、原暂停是否结束、名额是否足够；成功则等恢复任务完成。原本 active 的手动暂停空间需超级管理员恢复 |
| 模板改了个人技能没变 | 用户使用独立副本，需自行更新或重新复制 |
| 重置后仍不能登录 | 账号是否停用、是否用新密码、是否触发短期限流 |

向运维提供账号名、操作时间、空间状态、任务 ID 和错误摘要即可，不要把密码、密钥、插件凭据或业务全文放入共享文档。

### 8. 当前管理能力边界

当前页面没有既有账号角色升降级、批量导入、账号永久删除、逐用户资源配额调节、任意模型协议适配、自动安装全部插件依赖、自动开通数据库或外网、强制更新全部个人技能、全部历史审计导出或超级管理员代替用户进入业务内容的功能。

“发布成功”“配置保存”“空间就绪”“连接测试通过”“实际业务工具调用成功”是不同验收层次，培训时应按各自准确含义说明。

## 完整练习：从一份表格到分析结果

本练习使用合成数据，目的是熟悉操作。管理员需提前给练习账号授权可用模型，并保证空间已就绪。

### 第一步：准备合成文件

在自己电脑上创建 UTF-8 编码的 `示例统计.csv`，内容如下：

```csv
日期,类别,数量,金额
2026-09-01,甲类,3,120
2026-09-01,乙类,2,80
2026-09-02,甲类,4,160
2026-09-02,乙类,1,40
```

这四行记录的数量合计为 10、金额合计为 400；甲类数量 7、金额 280，乙类数量 3、金额 120。可以用这些人工核对值检查结果。

### 第二步：上传并查看来源

1. 进入“我的文件”，上传 `示例统计.csv`。
2. 等待该文件变为可引用的解析完成状态。
3. 打开预览，核对表头、四条数据和行位置是否被提取。
4. 如果出现乱码，先在本机将原文件转存为 UTF-8 后重新上传；重新上传会产生新文件记录，不覆盖旧记录。

### 第三步：准备一个个人技能

按“分析技能”的创建流程填写：

- 技能名称：`表格汇总助手`。
- 用途：`对用户提供的表格进行汇总，并指出资料范围与核对方法。`
- 技能内容：

```text
只分析用户在当前问题中提供的资料。
先说明使用了哪些文件及来源行，再列出分类汇总和合计。
遇到缺失字段、单位不明或无法计算的数据，明确说明，不自行补造。
给出可人工复核的计算过程。资料不足时先向用户询问。
```

保存后等待更新结束，再点击“测试”，查看“技能生效检查”结果。检查通过后，回到对话中选择该技能。

### 第四步：在对话中引用文件

新建会话，选择刚才的文件和技能，发送：

```text
请使用我选择的技能分析“示例统计.csv”。
按类别汇总数量和金额，并给出全表合计。
请说明使用的文件和来源行，列出可以人工复核的计算过程。
```

对照第一步的人工核对值，检查模型有没有遗漏行、重复计算或混淆字段。文件和技能标签在发送后仍会保留；继续追问前应检查当前选择项，移除不再需要的资料。点击“新建对话”会清空选择，所有上传文件不会自动进入每次对话。

### 第五步：生成并下载结果

如果需要下载，继续明确要求：

```text
请把上述已核对的汇总写成一个 Markdown 结果文件，文件名为“示例统计汇总.md”，完成后告诉我。
```

等待实际文件写入完成，然后到“我的文件”的成果区域查找并下载。仅在回答中出现文件名，不代表磁盘上已生成文件；应以成果列表与可成功下载为准。当前不承诺模型可以直接生成任意格式的 Office 文档。

### 第六步：练习结束

检查会话历史能够重新打开。需要保留时，可以重命名会话；无需保留的上传原件和测试会话可通过各自页面删除。成果文件和上传文件是两类资源，不要把删除上传记录理解为自动删除全部对话成果。

插件练习另行执行：超级管理员发布并授权合成插件后，用户先安装、填写配置并等待生效，再运行连接测试，最后在对话中明确请求调用该插件。不要把测试插件返回的标记当作真实业务查询结果。

## Python 接入与公开 API

### 连接哪一个服务

当前本机控制台 origin 为 `http://127.0.0.1:14090`，公开业务 API 前缀为 `/api/console/v1`。Python 应连接统一控制台，不能直接使用旧实例端口、私有 Gateway、原生 OpenCode SDK 或 Worker 接口来替代本文接口。

现有 [httpx 客户端示例](../../services/peixian-control/examples/console_client.py) 已包含登录、文件、会话、SSE、发送与停止逻辑；优先复用，不必另造一套 SDK。它是本仓库的 Python 示例类，不是 OpenCode 官方 Python SDK，也未发布为可直接 `pip install` 的包。完整契约见 [OpenAPI](../../services/peixian-control/docs/openapi.json)。

`ConsoleClient(base_url=...)` 和 CLI 的 `--base-url` 只接收 origin，例如 `http://127.0.0.1:14090` 或正式 HTTPS 域名；不要附加 `/api/console/v1`。类内部会添加前缀，且拒绝 URL 用户信息、查询参数或非根路径。部署在别的电脑时，`127.0.0.1` 指客户端自己，需要管理员提供实际入口或已配置的 SSH 转发，不能仅替换端口猜测服务。

### 账号、Cookie 与个人令牌

| 方式 | 适合用途 | 认证与写请求 |
| --- | --- | --- |
| 浏览器同源 Cookie | 普通交互登录 | `px_session` 为 HttpOnly、SameSite=Strict，最长 8 小时；写请求使用登录或 `/me` 返回的 `X-CSRF-Token`，并校验 Origin |
| Python Cookie 会话 | 交互输入账号密码，不长期保存令牌 | 复用 `ConsoleClient.login()`，客户端自动保存 Cookie 和 CSRF；首次密码需先修改 |
| Python Bearer | 已获得个人令牌的脚本 | `Authorization: Bearer <个人令牌>`；不需要 Cookie 的 CSRF 头，权限仍是该令牌所属账号的权限 |

同一账号换电脑仍访问自己的环境。请求中没有可选的 tenant、账号、目录或工作区参数；文件、会话、技能 ID 必须属于当前账号。超级管理员或管理员令牌都不会因此获得普通用户会话、文件或普通用户模型调用接口的访问权。业务脚本应使用普通用户自己的令牌。

先用浏览器完成首次改密，再在个人令牌管理中创建令牌。原始令牌只在创建时返回一次，默认有效期 30 天；后续列表只有 ID、名称和时间。不要把令牌 ID、浏览器 Cookie、模型 API Key、`X-Worker-Key` 或 `X-Peixian-Key` 当作个人 Bearer 令牌。

程序创建令牌时，`POST /tokens` 的请求体为 `{"name":"Python client"}`，响应为 `{"token":"仅本次返回的原始值","item":{"id":"令牌ID","name":"名称","created":0,"expires":0}}`。这里 created/expires 的 0 仅说明时间戳字段位置，实际值由服务端生成。撤销使用 `DELETE /tokens/{id}`。脚本不要打印或记录整个创建响应。

**关闭客户端不等于注销。** `async with ConsoleClient(...)` 结束只关闭 HTTP 连接；调用 `logout()` 会执行 `/auth/logout` 并撤销当前认证。使用 Bearer 时，它会撤销当前个人令牌，而不是单纯清理本机对象。撤销、停用或过期也会让关联的旧 SSE 连接关闭。

### Windows：使用现有项目 Python

在 PowerShell 中先定义路径；这些命令本身不调用接口：

```powershell
Set-Location -LiteralPath 'D:\Code\PeiXianDB\opencode'
$consolePython = Join-Path (Get-Location) 'services/peixian-control/.venv/Scripts/python.exe'
$consoleExample = Join-Path (Get-Location) 'services/peixian-control/examples/console_client.py'
$consoleOrigin = 'http://127.0.0.1:14090'
& $consolePython --version
& $consolePython $consoleExample --help
```

上面使用控制层的 `.venv`，不是旧一期 `deploy/peixian/.venv`。若环境不存在，按控制层 README 为 Python 3.12 准备隔离环境和锁定依赖；不要修改其他项目的 Python 包。

个人令牌可用安全输入临时放入当前 PowerShell 进程的环境，避免将明文直接写入命令历史：

```powershell
$consoleSecureToken = Read-Host '输入自己的个人令牌' -AsSecureString
$consoleTokenPointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($consoleSecureToken)
try {
    $env:PEIXIAN_CONSOLE_TOKEN = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($consoleTokenPointer)
} finally {
    [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($consoleTokenPointer)
    $consoleSecureToken.Dispose()
}
```

该环境变量只是向当前进程及其子进程传值，不是加密存储；不要使用 `setx`、提交 `.env`、输出环境变量或把令牌放进 URL/参数。运行结束后清除：

```powershell
Remove-Item Env:PEIXIAN_CONSOLE_TOKEN -ErrorAction SilentlyContinue
```

若不设置令牌，CLI 会用 `getpass` 交互读取密码；初始密码还会交互要求修改。**CLI 没有只读探测模式：除 `--help` 与 `--abort-only` 外，它会按默认或指定问题调用真实模型。**

### 只读检查：身份、授权模型、文件与会话

下面复用现有客户端，只读取元数据，不上传文件、不创建会话、不发送模型请求。把代码保存为 `deploy/peixian/.runtime/python-readonly.py`；该文件名仅是使用示例，本文不会替你创建或运行它。

```python
import asyncio
import os
import httpx
from examples.console_client import ConsoleClient, ConsoleError

async def main():
    token = os.environ.get("PEIXIAN_CONSOLE_TOKEN")
    if not token:
        raise ConsoleError("Set PEIXIAN_CONSOLE_TOKEN in the current process")
    async with ConsoleClient("http://127.0.0.1:14090", token=token) as client:
        user = await client.me()
        print("Role:", user["role"])
        print("Must change password:", user["must_change_password"])
        print("Runtime status:", (user.get("runtime") or {}).get("status"))
        models = await client.models()
        print("Authorized models:", [{"id": m["id"], "name": m["name"]} for m in models])
        print("Uploaded file count:", len(await client.files()))
        print("Session count:", len(await client.sessions()))

try:
    asyncio.run(main())
except ConsoleError as error:
    print(str(error))
    raise SystemExit(1) from None
except (httpx.HTTPError, TimeoutError, OSError) as error:
    print("Read failed:", type(error).__name__)
    raise SystemExit(1) from None
```

从仓库根目录运行该用户自行保存的文件：

```powershell
$env:PYTHONPATH = (Resolve-Path 'services/peixian-control').Path
& $consolePython 'deploy/peixian/.runtime/python-readonly.py'
```

这里模型列表的 `id` 才是发送消息时的 `model_id`。`name` 是展示名；管理员配置的上游 `deepseek-flash` 或 vLLM 模型名称是另一层映射，不应直接填入普通用户请求。为空时请联系管理员授权。环境非 ready 时，文件和会话读取可能返回 409/503，不能因此认定账号不存在。

### 文件上传、等待解析与下载

这组操作会创建自己的上传文件，并在本机写入下载副本；**不会调用模型**。它复用 `upload`、`wait_for_file` 和 `download`，不自行构造 Gateway 路径。示例可保存为 `.runtime/python-files.py`，与前一节使用同一 PYTHONPATH 和解释器运行。

```python
import asyncio
import os
from pathlib import Path
import httpx
from examples.console_client import ConsoleClient, ConsoleError

async def main():
    token = os.environ.get("PEIXIAN_CONSOLE_TOKEN")
    if not token:
        raise ConsoleError("Personal token is required")
    source = Path(input("Local file path: ").strip())
    destination = Path("deploy/peixian/.runtime") / ("downloaded-" + source.name)
    if destination.exists():
        raise ValueError("Choose a new local output name; existing files are not overwritten")
    async with ConsoleClient("http://127.0.0.1:14090", token=token) as client:
        uploaded = await client.upload(source)
        print("File ID:", uploaded["id"])
        parsed = await client.wait_for_file(uploaded["id"], timeout=90)
        print("Parse status:", parsed["status"], "Source chunks:", len(parsed["chunks"]))
        await client.download(uploaded["id"], destination)
        print("Download completed.")
        # 如需删除这次已确认无用的上传文件，另行显式调用：
        # await client.delete_file(uploaded["id"])

try:
    asyncio.run(main())
except ConsoleError as error:
    print(str(error))
    raise SystemExit(1) from None
except (httpx.HTTPError, TimeoutError, ValueError, OSError) as error:
    print("File operation failed:", type(error).__name__)
    raise SystemExit(1) from None
```

上传 HTTP 请求为 multipart/form-data，字段名必须为 `file`，不要手动拼写含边界的 Content-Type。HTTP 202 响应直接是文件元数据对象，包括 `id`、`name`、`size`、`status`、`truncated` 等；不是 `{items:...}`，也不代表解析结束。ID 是服务端不透明标识，不是本地路径。

`GET /files/{id}/text` 返回：

```json
{
  "text": "已提取的文本",
  "chunks": [{"text": "某一段文本", "source": {"type": "pdf", "page": 1}}],
  "truncated": false,
  "status": "ready",
  "name": "用户上传文件名.pdf"
}
```

这里 `source` 只是 PDF 页来源示例，CSV、XLSX、TXT、DOCX 有各自的行、工作表、段落或表格来源；不要硬编码所有格式都有 `page`。

文件状态可能为 uploading、queued、parsing、ready、partial、no_text、unsupported 或 failed。`wait_for_file` 只在 ready 且未截断时返回，partial 或 truncated=true 会立即抛出 `ConsoleError`。扫描 PDF 不做 OCR；加密、损坏或超资源文档不能当作解析成功。

单文件最多 20 MiB，每账号原始上传共 1 GiB；解析最多一百万字符、10,000 个来源块。预览另限 20,000 字符和 100 个来源块，**预览被截断不等于原文件部分解析**。模型引用依据 `/text`；服务器会对 partial/truncated 的引用返回 413，要求拆分后重新上传。解析 ready 也不保证整份资料适合单次模型上下文。

每次重复上传，即使名称相同，也会得到不同 ID。下载返回原始字节；`download` 使用独占创建，不覆盖已有本地文件，失败时删除本次未完成副本。模型生成的结果文件另在 `GET /results` 列出，调用 `download(result_id, destination, result=True)` 下载，不能把结果 ID 填进上传文件的 `file_ids`。

### 会话与真实模型调用

`create_session(title)` 只创建空会话；真正调用模型的是 `send_message` 或 `run_message`。以下 CLI 示例均会调用真实授权模型，应由使用者确认所选模型和资料后执行。当前使用的是哪种模型服务，以管理员配置及本账号 `/models` 结果为准；本文不将官方 API 调用等同于内网 vLLM 联调通过。

如果已经设置个人令牌，用前面的只读检查选出平台模型 ID，然后执行：

```powershell
$consoleModelId = Read-Host '输入本账号授权模型的平台 ID'
& $consolePython $consoleExample --base-url $consoleOrigin --model-id $consoleModelId --message '请用两句话说明你的用途。' --timeout 180
```

没有个人令牌时，去掉环境变量即可让现有脚本交互读取普通账号密码：

```powershell
Remove-Item Env:PEIXIAN_CONSOLE_TOKEN -ErrorAction SilentlyContinue
& $consolePython $consoleExample --base-url $consoleOrigin --username '你的普通账号' --message '请用两句话说明你的用途。'
```

CLI 输出本次使用的 Session ID。继续已有会话时传 `--session-id`；附文件用 `--file`，附已启用个人技能用 `--skill-id`，这两个选项都可重复，分别最多五项：

```powershell
$consoleSessionId = Read-Host '输入自己的会话 ID'
$consoleSourceFile = Read-Host '输入要上传的本地文件完整路径'
$consoleSkillId = Read-Host '输入自己的已启用技能 ID'
& $consolePython $consoleExample --base-url $consoleOrigin --session-id $consoleSessionId --model-id $consoleModelId --file $consoleSourceFile --skill-id $consoleSkillId --message '请使用所选技能分析资料，标明引用来源。'
```

`--file` 总会重新上传本地文件；CLI 没有 `--file-id`。需要复用已上传文件时，用现有类方法 `run_message(..., file_ids=[已解析文件ID])`。技能 ID 可来自 `client.request("GET", "/skills")` 返回对象的 `items`，不是技能名称或磁盘路径。插件按已安装和生效的配置供模型选择，没有可提交的 `plugin_ids` 消息字段。

发送的公开 JSON **只接受以下四个字段**：

```json
{
  "text": "要分析的问题",
  "model_id": "从本账号模型列表取得的平台ID",
  "skill_ids": [],
  "file_ids": []
}
```

请求路径为 `POST /api/console/v1/sessions/{sid}/messages`。只有 text 必填，不能为空白；model_id 省略时由服务端选择授权列表中的默认项，建议业务脚本显式传入已选的平台 ID。每次文字最多 32,000 字符；文字、选中技能内容和带来源的文件引用另合计限制 18,000 UTF-8 字节，文件引用还有 24,000 字符总预算。超限明确返回 413，不会自动裁掉尾部继续提交。

成功响应为 `202 {"accepted":true,"run_id":"回执ID"}`。**run_id 不是消息 ID，也没有 `/runs/{run_id}` 查询接口；202 不代表模型已完成。** `send_message` 只返回该回执。`run_message` 先订阅事件，再发送、刷新消息与会话状态，确认新的助手消息已有完成时间且会话 idle 后才返回。

### SSE 与消息读取

`GET /events` 是当前账号的刷新通知流，不是 OpenAI chat-completions 的 token delta 流。线上帧如下，每个事件由空行结束：

```text
event: change
data: {"type":"connected"}

event: change
data: {"type":"updated"}

: heartbeat

```

`ConsoleClient.events()` 产出 `{"event":"change","data":"JSON字符串"}`；data 仍需 `json.loads`，并非已解析对象。心跳是注释，不是回答。事件不包含 token、正文、会话 ID 或原始工具参数，也没有可靠事件重播协议。收到更新后读取 `GET /sessions/{sid}/messages`，同时从 `GET /sessions` 查看对应会话状态。

消息接口响应为 `{ "items": [...] }`。每条消息包含 `info` 与 `parts`；`info.id` 是真正的消息 ID，`info.role` 区分 user/assistant，`info.time.completed` 用于识别完成，错误时可能有 `info.error.message`。正文是 `parts` 中 type=text 的 text；工具项只含经过筛选的中文标题、状态与允许展示的 inputs/outputs，不返回原始内部负载。

流式读取会反复返回同一消息的完整当前快照。客户端应按 `info.id`、片段 ID 覆盖更新，不能把每次整个 text 再追加，否则会重复显示。现有 `run_message(..., on_update=同步函数)` 会把本次新增助手消息的当前快照传给回调；它最终返回整个会话历史，CLI 也会输出历史中全部助手正文。继续会话时重复打印旧回答是当前示例行为，不代表服务重复生成。

控制层只在有界内存中暂存原生未持久化的助手正文；原生完成记录优先。断线交接会丢弃可能有缺口的临时内容，不提供 delta 重播；最终历史依赖原生持久化记录。使用现有 `run_message` 的刷新逻辑即可，不要把 SSE 断开当作成功完成，也不要通过原生 OpenCode 事件绕过公开过滤。

### 停止生成与异常恢复

使用同一普通账号的有效认证，在另一个终端执行：

```powershell
$consoleSessionId = Read-Host '输入要停止的自己的会话 ID'
& $consolePython $consoleExample --base-url $consoleOrigin --abort-only $consoleSessionId
```

`--abort-only` 不创建新会话、不上传文件、不发起模型请求，只对指定会话调用 `POST /sessions/{sid}/abort`，成功响应为 `{"ok":true}`。这表示已发出停止操作；随后回读会话状态和消息，确认已停止并保留收到的内容。

现有 `run_message` 的超时、取消或运行错误，在已确认提交后会尝试 abort 再结束事件订阅。CLI 的 Ctrl+C 使用这条取消路径；强杀进程、网络断开或丢失提交响应不保证成功发出停止。需要时用上面的显式命令。一个会话应只有一个消息写入方，避免脚本和浏览器同时提交导致难以判断本次结果。

默认 `--timeout 180` 是接受消息后的等待预算，不包含之前上传、解析和连接准备的全部耗时。若模型提出业务问题或权限确认，单纯等待不能让其继续；现有 CLI 不提供交互答题向导，可在同账号网页处理待确认事项，或按 OpenAPI 实现明确的 `/questions`、`/permissions` 回复，不应自动批准所有操作。

错误处理建议：

| 情况 | 含义与处理 |
| --- | --- |
| 400 / 422 | 请求字段、ID 或格式不正确；依据 OpenAPI 修正，不原样循环重试 |
| 401 | 登录/令牌无效、到期或被撤销；重新取得有效认证 |
| 403 | 角色、模型授权、首次改密、CSRF/Origin 等限制；不要换填账号参数绕过 |
| 404 | 资源不存在、不可见或不属于当前账号；先列出自己的资源 |
| 409 | 环境未就绪、配置待应用、文件未解析完成或其他状态冲突；查询实际状态后处理 |
| 413 | 上传/配额、引用预算或部分解析限制；减少、拆分或删除自己已确认无用的原始上传 |
| 429 | 登录尝试或并发/频率达到限制；按提示等待 |
| 500 / 502 / 503 | 控制层或账号环境未能完成请求；保留错误码和 request_id（如果存在）供运维定位 |
| 网络错误 / TimeoutError | 结果可能未知，尤其在 POST 消息后；先查会话历史和状态，再决定是否停止或重新提交 |

常见错误 JSON 为 `{"message":"可展示的提示","code":"http_409","request_id":"定位标识"}`，部分请求大小中间件错误没有 request_id。不要假设所有非 2xx 都返回同样完整字段，也不要输出全部 HTTP 响应或请求头来排查认证。

`ConsoleClient` 对非 2xx 抛出 `ConsoleError("Console request failed (HTTP ...)")`，有意不回显服务端正文。网络库异常另为 `httpx.HTTPError`，解析等待及模型等待可产生 `TimeoutError`。对有副作用的发送操作不要自动重放：公开接口没有幂等键，网络超时后再次 POST 可能产生第二次请求。

### 公开接口速查

下表路径均相对于 `/api/console/v1`。列表类 HTTP 返回 `{items:[...]}`，现有客户端的 `models()`、`files()`、`sessions()`、`messages()` 已拆出列表；`me()` 则已拆出 user 对象。用 `request()` 调用时返回原 JSON。

| HTTP 操作 | 请求体 | HTTP 成功响应 |
| --- | --- | --- |
| POST /auth/login | `{username,password}` | 200 `{user,csrf_token}`，同时 Set-Cookie |
| GET /me | 无 | 200 `{user,csrf_token}`；个人令牌的 csrf_token 为 null |
| POST /me/password | `{current_password,password}` | 200 `{ok:true}`，撤销其他认证，保留本次认证 |
| POST /auth/logout | 无 | 200 `{ok:true}`，撤销当前认证 |
| GET /tokens | 无 | 200 `{items:[{id,name,created,expires}]}`，无原始令牌 |
| POST /tokens | `{name}` | 200 `{token,item}`，原始 token 只本次返回 |
| DELETE /tokens/{id} | 无 | 200 `{ok:true}` |
| GET /models | 无 | 200 `{items:[{id,name,description,is_default}]}`，只含已授权模型 |
| GET /files | 无 | 200 `{items:[文件元数据]}` |
| POST /files | multipart 的 `file` | 202 单个文件元数据，随后等待解析 |
| GET /files/{id}/text | 无 | 200 `{text,chunks,truncated,status,name}` |
| GET /files/{id}/preview | 无 | 200 同上，但另受预览预算限制 |
| GET /files/{id}/download | 无 | 200 原始二进制内容及附件文件名 |
| DELETE /files/{id} | 无 | 200 `{ok:true}`；解析中可能 409 |
| GET /results | 无 | 200 `{items:[结果元数据],truncated}` |
| GET /results/{id}/download | 无 | 200 该账号工作区的结果文件二进制内容 |
| GET /sessions | 无 | 200 `{items:[会话对象]}`，含 status |
| POST /sessions | `{title}` | 200 单个会话对象，含 id；尚未调用模型 |
| PATCH /sessions/{id} | `{title}` | 200 更新后的会话对象 |
| DELETE /sessions/{id} | 无 | 200 `{ok:true}`，删除会话需明确使用者意图 |
| GET /sessions/{id}/messages | 无 | 200 `{items:[{info,parts}]}` |
| POST /sessions/{id}/messages | `{text,model_id?,skill_ids?,file_ids?}` | 202 `{accepted:true,run_id}` |
| POST /sessions/{id}/abort | 无 | 200 `{ok:true}` |
| GET /events | 无 | 200 text/event-stream，change 事件及 heartbeat 注释 |

表格中的 `{字段}` 是结构速记，不是可以直接发送的 JSON；真实 JSON 必须为字段名与字符串加双引号。`user` 包含 id、username、role、active、must_change_password 和 runtime；runtime 可能为 null，否则包含 id、status、revision、desired、error。会话对象主要包含 id、title、time，可能有 parentID；只有列表接口显式追加 status。不要自行拼接不在契约中的 `/session`、`/v1/chat/completions`、`/runs`、`/files/{id}` 元数据详情或模型上游地址。

### Linux 客户端提示

服务端和 Python 客户端可以不在同一台机器，但必须能访问管理员提供的公开入口。Linux 不能直接使用 Windows `.venv/Scripts/python.exe`；在对应源码目录创建自己的 Python 3.12 环境或使用已准备的隔离环境。示例：


## 日常运维：启动、停止与迁移

本节面向维护当前 Windows 部署的人。普通用户的日常分析不需要执行命令。以下 Windows 命令均从仓库根目录执行；Linux 运维按照链接文档中的工作目录执行。

### 三角色升级与普通重启分开处理

三角色控制镜像采用独立标签 `peixian-control:console-r2-roles`，旧 r1 保留。首次从旧版升级前，必须先做角色/schema 兼容检查和控制库备份；不能把“up 成功”直接当成迁移验收，也不能把新 schema 交给不兼容旧镜像打开。具体检查、备份及迁移合同见 [三角色说明](ROLES.md)。

旧 admin 一次性升级为 super_admin，保留 UID、用户名和密码哈希，增加其认证版本并撤销被迁移旧管理员的 Cookie/Bearer；因此旧管理员升级后需要重新登录，个人程序令牌按实际需要重新创建。普通用户账号、卷和历史不因这次角色升级而迁移或删除。正式公共 Skill 审核流程不在这次 schema 迁移中实现。

### 电脑重启后恢复

确认 Docker Desktop 已启动并处于 Linux containers 模式。当前项目依赖专属 Python 环境和已构建镜像；已有部署正常恢复时不需要重新初始化、安装依赖或构建镜像。

```powershell
Set-Location -LiteralPath 'D:\Code\PeiXianDB\opencode'
.\deploy\peixian\console.ps1 -Action up
.\deploy\peixian\console.ps1 -Action worker-start
.\deploy\peixian\console.ps1 -Action status
Invoke-RestMethod -Uri 'http://127.0.0.1:14090/health'
```

预期结果：控制台容器健康，健康接口返回 `status: ok`。随后登录管理中心，核对各账号环境状态。

`status` 只列出公共控制台的 Compose 服务，不证明所有用户环境都正常，也不证明宿主执行器正在工作。健康接口同样只检查控制层，不检查模型是否能回答。

`worker-start` 启动一个隐藏的受跟踪 Python 进程；如果同一受跟踪进程已经在运行，会提示已运行。当前 Windows 交付没有注册开机任务或 Windows 服务，进程异常退出后也没有独立的自动拉起服务。电脑重启后需再次执行并核对。

### 常用命令分别做什么

| 命令或界面操作 | 实际范围 | 数据影响 |
| --- | --- | --- |
| `console.ps1 -Action up` | 做 schema/镜像兼容与必要备份检查，以校验返回的不可变 image_id 启动控制台 | 保留控制台数据卷；首次角色升级会迁移控制库 |
| `console.ps1 -Action start` | 同样先校验并固定该次检查返回的 image_id 启动 | 同上 |
| `console.ps1 -Action backup` | Worker 已停且控制卷无运行消费者时备份 control-data | 含控制库与发布包，不含用户卷和独立密钥 |
| `console.ps1 -Action status` | 查看公共控制台容器状态 | 只读 |
| `console.ps1 -Action worker-start` | 启动负责账号生命周期和配置应用的宿主执行器 | 不主动清空任何账号数据 |
| `console.ps1 -Action worker` | 在当前终端前台运行执行器，适合维护诊断 | 不应与后台执行器并行运行 |
| `console.ps1 -Action worker-stop` | 检查没有活动任务后停止受跟踪执行器 | 保留现有容器及数据；任务忙或无法确认时拒绝停止 |
| `console.ps1 -Action stop` | 只停止公共控制台 | 不会自动停止所有账号，也不会停止宿主执行器 |
| 超级管理员在管理中心暂停某账号空间 | 通过执行器停止该账号的运行服务 | 保留会话、文件和配置；释放运行名额 |
| 管理中心停用账号 | 禁止账号继续使用并安排环境暂停 | 撤销该账号认证，保留数据 |
| `console.ps1 -Action build` | 构建前端及三个项目镜像 | 属于版本维护步骤；构建成功不表示现有账号已切换镜像 |
| `console.ps1 -Action export` | 导出三个镜像和校验文件 | 导出物不是账号数据备份 |

不要将旧一期的 `manage.ps1` 或 `deepseek.ps1` 用作当前控制台的日常启停命令。

### 有计划地停止整个工作台

1. 提前通知使用者结束工作；由超级管理员在管理中心按账号暂停需要停下的空间，等待相关任务完成。
2. 保持控制台可用，执行 `console.ps1 -Action worker-stop`。如提示有任务或无法确认，先排查，不强制结束进程。
3. 执行 `console.ps1 -Action stop` 停止公共入口。
4. 需要恢复时先 `up`、再 `worker-start`，然后由超级管理员在管理中心恢复相应普通用户空间。

仅关闭浏览器不会停止服务或释放账号的容器资源。暂停后保留的数据也仍然占用磁盘空间。

### 资源与容量

默认最多同时保留 4 个普通用户运行名额，超级管理员与管理员均没有普通用户运行环境。已暂停账号保留记录与数据，恢复时重新申请名额；其他账号占满名额时，恢复可能失败。

| 组成 | 每账号 CPU 上限 | 每账号内存上限 |
| --- | ---: | ---: |
| OpenCode Agent | 2 | 2 GiB |
| 文件与 API 网关 | 0.5 | 512 MiB |
| 模型出口 | 0.5 | 128 MiB |
| 合计 | 3 | 2.625 GiB |

公共控制台额外限制为 1 CPU、512 MiB。上述值是容器资源上限，不是空闲时固定占用；模型推理资源在实际模型服务器或 API 服务侧计算。

按默认四账号的保守预算，宿主执行器还检查 Docker 引擎的 CPU、内存总预算，四账号连同公共服务和 1 GiB 余量约需要 13 CPU 的预算、至少 12 GiB 内存。只修改页面配置或一个环境变量，不会自动完成整套容量规划。当前 1 GiB 上传配额不限制全部成果、解析产物或 HOME 卷，维护人员应另行监控磁盘空间。

### 从其他电脑访问

本机默认 `14090` 只绑定回环地址。服务器具备 SSH 时，可以由维护人员开通 SSH 本地转发：

```sh
ssh -N -L 14090:127.0.0.1:14090 <服务器运维账号>@<服务器地址>
```

保持该终端连接，在客户端浏览器打开 `http://127.0.0.1:14090/`。客户端本地同名端口需可用；占用时由维护人员明确更换端口并同步允许的 Origin。

正式内网域名访问需要维护人员同时配置入口代理、TLS、准确的 `CONSOLE_ORIGINS`、HTTPS Cookie 选项及访问策略。不能只把 `127.0.0.1` 改成 `0.0.0.0` 就认定部署完成。当前账号之间仍通过平台认证和独立环境隔离。

### 自部署 vLLM 与内网业务接口

管理员在模型管理中配置模型出口能够到达的 OpenAI 兼容 `/v1` 地址、实际模型 ID 和该服务的凭据，再为用户授权。普通用户选择的是界面名称，对话请求提交的是平台分配的模型 ID。

需要由维护人员验证的是模型出口容器到目标服务的网络，而不只是浏览器或宿主能访问。不要把宿主上的 `127.0.0.1` 直接当作容器内可访问的宿主模型地址。

当前已执行的真实模型验收使用 DeepSeek 官方服务。vLLM 的兼容协议已经做过接口测试，但尚未提供并接通真实内网 vLLM 地址；不能把填写配置示例当作内网联调完成。当前使用插件不要求额外建设 MCP 服务器；真实插件访问内网数据服务仍需同时设计接口、权限、凭据和允许的网络路径，安装插件本身不会自动开放网络。

### 备份和迁移的边界

镜像导出文件位于 `deploy/peixian/dist/console/`，用于保存软件运行镜像；源码与镜像均不能替代账号数据备份。

完整恢复至少涉及：控制数据库、插件发布包、对应的加密主密钥、宿主执行器状态与发布记录、各账号 HOME/workspace/files 数据卷。备份必须在一致性边界下进行，凭据采用受控存储。不要只复制 SQLite 主文件就认定在线数据库备份完整。

现有 `console-migrate.py` 的快照与导入流程专门面向旧 A/B 迁移，它不是新账号环境的通用一键备份工具。不要将它套用于全部托管账号，也不要在已迁移环境重复执行迁移作为日常恢复操作。

正式迁移、离线镜像准备、Linux ACL 和 systemd 示例，见 [运行与迁移说明](CONSOLE_OPERATIONS.md)。所有恢复操作应先保留当前数据，再选择正确的软件、数据与密钥组合；不使用删除卷的方式解决登录、配置或模型连接问题。

## 常见问题与排查顺序

### 超级管理员已经启用了插件，为什么用户看不到？

按下面顺序检查：

1. 管理中心的插件是否存在至少一个已启用版本。
2. “用户管理”中选择的是目标账号，例如 `client-a`，而不是名字相近的测试账号。
3. 点击该账号行的“授权”，确认“授权插件”已勾选，然后点击“保存授权”。只有勾选没有保存不会写入后台。
4. 普通用户在自己的浏览器刷新页面，再进入“业务插件”。当前页面没有专门的手动刷新按钮；已打开页面的授权变化可能不会立即刷新，切换到其他页面再回来也可重新加载。
5. 查看是否出现“可安装”卡片。授权控制可见性，安装和配置控制实际运行；用户无需先安装才能看见目录。

超级管理员插件授权界面可能仍列出所有版本均被停用的插件供选择。若账号已经保存授权但目录仍为空，应回到“插件发布”检查版本是否可用。

### 插件看得见，但为什么对话中没有调用？

依次检查是否已安装、所选版本可用、必要配置是否填写、是否已启用、个人空间是否更新完成。支持连接测试的插件可先测试，再在问题中明确请求调用插件功能。模型是否选择工具还受模型能力、问题表达和当前工具权限影响；连接测试通过不保证每次问题都会触发该工具。

没有声明 `test` 入口的插件会提示未提供连接测试，不能把这个状态当作测试成功或必然失败。真实业务插件尚未开发时，合成插件只返回验收用信息。

### 保存后一直显示更新中或待生效

已有任务正在生成时，系统会先等待。默认等待 5 分钟仍未空闲时保留待生效，不强行结束用户当前任务。还应检查宿主执行器是否运行、管理中心任务有无失败、Docker 资源是否充足、模型或插件配置是否有效。

保存成功不代表运行实例已重新加载。不要连续重复点击保存来催促更新。维护人员应查看该账号任务与错误编号，按账号处理；不需要因此重启其他用户环境。

### 为什么上传成功了，却不能选择文件提问？

上传完成后还需要解析。等待处理、解析中、不支持、没有可提取文字、处理失败或部分解析文件不能当作全文引用。预览截断与解析截断是两回事：短预览只影响页面展示，解析产物不完整则必须拆分重传。

本期没有扫描件 OCR。对于图片型 PDF，需要先在独立工具中获得可用文字层或转换为支持的文本资料。加密文件应由有权处理的人在本机解除保护后重新上传。

### 文件不大，为什么提示内容超出范围？

20 MiB 是上传体积上限；发送给模型还有更小的上下文预算。单次最多 5 个文件、5 个技能，问题、技能与带来源文件内容合计最多 18,000 UTF-8 字节。中文通常占多个字节，不能把它当作 18,000 个汉字或 18,000 个 token。

可以减少选中的资料、分工作表或按页拆分、缩短技能，再分次提问。系统不会静默删掉文件尾部后宣称完成全文分析。

### 为什么 Excel 汇总与我看到的结果不同？

解析只读取文件中保存的单元格值与已有公式缓存，不执行 Excel 公式。公式没有保存缓存、数据单位不清、合并单元格、隐藏信息或图表中的含义，都可能需要额外说明。先对照预览核实输入；必要时在办公软件中保存计算结果或导出一份仅含值的表格后再上传。

### 没有模型可选，或者发送后提示模型不可用

由管理员检查连接是否启用、目标账号是否获得模型授权、实际模型 ID 是否正确、服务地址和凭据是否有效，再等待账号配置应用完成。只有一个授权模型时不展示额外的模型切换操作，这是正常行为。

用户输入框中填写 `deepseek-flash` 或其他上游模型名称，不会替代平台授权；Python 同样必须使用 `/models` 返回的模型 ID。

### 回复停住、断线或点击停止后还有部分文字

断线时先保持当前页面，等待重连；必要时重新进入该历史会话读取已保存的消息。停止生成会保留已经产生的部分内容，不等于删除本次问题或保证模型上游完全不产生费用。网络中断期间的临时增量可能不连续，最终以保存的会话历史为准。

如果请求结果不确定，先查看历史和忙闲状态，不要立即重发同一个问题，避免重复执行或产生重复模型请求。

### 登录失效、程序令牌失效

浏览器登录会话最长 8 小时，个人程序令牌有效期 30 天。在当前浏览器主动修改密码后，本次登录保留，其他浏览器会话和已有程序令牌失效；管理员重置密码后需要使用新密码重新登录并完成首次改密；账号停用后不能继续访问。

网页登录退出撤销当前登录会话；在个人设置中撤销某个程序令牌，只针对对应令牌。Python 使用 Bearer 令牌调用退出接口时，会撤销当前令牌；只是结束脚本应关闭客户端，不要把退出接口当作无副作用的连接关闭操作。

### 创建或恢复账号失败

先查看管理中心中该账号的环境和任务状态。常见原因包括没有可用运行名额、Docker 引擎预算不足、宿主执行器未运行、固定镜像不存在或配置发布失败。保留已有账号和卷，修正原因后通过界面重试或恢复；不要通过反复新建同名账号或删除数据卷来绕过错误。

### 页面还是“添加项目”，或者找不到管理中心

当前中文控制台入口是 `14090`。原生 OpenCode 页面属于旧独立入口，操作方式不同。普通账号不显示“管理中心”；超级管理员和管理员均有管理中心，但页签和动作不同。窄屏时先打开导航菜单查找功能入口。

### 向维护人员反馈什么

提供：出错时间、账号名称、所在页面、操作步骤、预期和实际结果、页面错误编号、必要的脱敏截图。模型问题补充界面模型名称；文件问题补充扩展名、体积和解析状态；插件问题补充名称、版本、是否启用及生效状态。

不要在工单或公共文档中附带登录密码、完整程序令牌、模型密钥、插件凭据或未经许可的文件正文。保留错误编号、发生时间和操作步骤，供维护人员辅助定位；并非每类错误都有可按该编号直接查询的独立日志。
