# 盗窃资料查询合成接入 V1

本目录提供六个独立只读插件及合成契约服务，不是供应方真实接口适配。固定服务端映射两名 DEMO 对象及两个虚构位置；不接受真实姓名、证件或任意地址。与既有七个资料插件并存，不删除已有插件、会话或资料。

## 执行边界

用户检查范围并确认 → Control 将签名计划、配置版本和助手身份冻结到 Run → Agent 只调用选定工具且参数为 `{}` → Gateway 注入冻结的请求 → 当前账号专属 Relay 的固定服务连接 → 私网合成服务。Agent 不持有服务凭据；模型不能提供 URL、方法、人员筛选或自动翻页。

六插件 ID 为 `peixian-theft-incidents/captures/tracks/warnings/warning-detail/warning-logs`，分别暴露 `peixian_query_` 加 `incidents/captures/tracks/warnings/warning_detail/warning_logs`。版本为 1.0.0。`python package.py <空输出目录>` 生成六包，已存在的包拒绝覆盖。

连接仅声明各自固定接口及 `/health`；详情和明细只允许两个合成对象的完整路径。GET 预警列表参数采用完整日期；警情半径公里、抓拍半径米，平台表单统一输入米并显式转换。服务拒绝额外字段、错误方法和无鉴权请求。

## 使用路径

- 选择“盗窃资料查询”，选资料、对象/位置、日期和范围，点击“检查范围”，再“确认并查询”。不会因为检查范围调用模型。
- 警情结果展开后可选“以此位置核对抓拍范围”；抓拍结果可明确选对象核对轨迹/来源预警。
- 轨迹中有明确来源映射的位置可选“以此地点核对警情范围”。无位置映射时不显示该操作。
- “解释已有结果”“展开依据”“继续”只说明当前会话已冻结来源，不重新取数。其他更换范围要求重新确认，不静默映射到旧对象。
- 终态 Run 可追加人工复核记录；追加更正保留旧记录，仅本人可访问。报告单独附复核意见，不修改原始 Claim、图谱或结果摘要。

## 数据语义

`cjsj` 只作为处警时间。抓拍汇总次数不等于到访次数，来源预警类型数量不等于独立事件数；不展示扣分、照片及个人嫌疑排名。轨迹覆盖总量未知、预警明细固定最近七天、分页结果仅当前页。坐标系未确认，不计算精确距离。图谱只画已确认对象与来源记录归属，不推断人物关系或到达现场。

## 部署与回退

Control schema v10 新增 append-only `run_reviews`；其余来源和状态继续存于 schema v9 已有加密快照及结果表。9→10 必须冻结、排空、停止写入并完整备份，然后显式 `PX_ALLOW_V10_MIGRATION=1`；结构、迁移脚本和祖先指纹校验均不可跳过。旧 v9 镜像不能连接 v10。

新能力须开启 `feature_scopes.theft_provider_v1` 对应账号，同时保留 task_spec、multi_agent、trusted_result 原白名单，并满足实际插件授权、安装、生效。Control、Gateway、宿主执行器使用匹配源码；发布前核对线上镜像未被替换。回退使用兼容 v10 镜像，或成套备份恢复到空命名空间，禁止覆盖新增数据。

`service.py` 通过 `THEFT_FIXTURE_HOST/PORT/KEY_FILE` 配置，仅允许私有非通配地址，默认本机回环 19463。密钥在服务器私密文件，禁止入 Git。运行时设置 `PYTHONPATH` 到 `services/peixian-control`。

## 真实接口待确认

登录 RSA/明文冲突、坐标系、时间参数边界、跨小区明细、夜间明细形态、稳定行标识仍需供应方澄清。真实接口未调用；人员评分/排名、批量筛嫌及写接口不属于本实现。
