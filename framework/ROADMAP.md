# 从初始化版到可复用开发框架

## 0.1：框架初始化（本轮）

- 保留沛县检查点与原工作树，新增独立框架分支。
- 保持 SolidJS + FastAPI，统一品牌与项目公开配置。
- 新项目生成器仅导出已提交模板，记录来源；排除密钥、状态和旧迁移材料。
- 独立控制部署定义、Cookie、资源命名空间和状态身份检查；默认禁用旧卷接管。
- 验证配置、脚手架、认证命名隔离与原行为兼容；不启动新框架替换原运行服务。

## 0.2：真正提高业务开发效率

1. **业务模块注册器与样例**：用“资料台账”完成前端页面、API、数据表、验证和账号归属，形成可复制约定。
2. **权限系统**：角色、权限点、页面/按钮权限与后端校验；先保留现有超级管理员和普通用户行为，再增加多角色。部门、岗位、组织数据范围根据首个业务项目实际需求加入。
3. **数据库迁移**：平台及业务实体版本记录、升级前检查与失败恢复；不靠应用启动时随意改表。
4. **开发生成器**：从实体描述生成 schema、repository/service/router、列表/表单和必要测试，默认生成归属校验；生成到业务目录，不覆盖框架核心。

验收应是开发者只修改业务定义，就能完成一个有权限、有数据归属、有前端表单的可运行模块，而不只是生成文件数量。

## 0.3：AI 扩展开发套件

- 插件项目模板、Schema 校验、打包与本地合成测试工具。
- Skill 模板、来源说明、版本与效果用例。
- 统一工具执行与业务确认展示合同；提供无敏感信息的开发诊断模式。
- 一个假数据接口插件样例，证明可安装、配置、调用、升级和回退。

## 0.4：发布与长期维护

- 框架版本、变更日志、模板升级比较和兼容矩阵。
- CI 中执行权限/隔离、迁移、接口、类型与 UI 检查。
- 离线镜像及依赖交付、配置清单、备份恢复演练。
- 按真实负载决定 PostgreSQL、对象存储、后台队列和多项目调度；当前不承诺多副本、跨主机调度或 Kubernetes。

建议先完成 0.2 的一个闭环业务模块，再扩充平台菜单数量。统一登录、组织权限、代码生成器不是本轮已完成的能力。
