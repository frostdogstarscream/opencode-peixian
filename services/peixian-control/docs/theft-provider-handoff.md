# 盗窃资料核对：使用与部署交接

## 已交付范围

本版本提供六个独立只读查询插件、明确范围确认、单次持久 Run、中文来源说明、来源图谱及本人追加复核。支持两种操作顺序：选警情后核对抓拍/轨迹，或选定对象轨迹后核对地点相关警情。

当前运行的是合成契约服务，只允许两个 DEMO 对象和两个 DEMO 来源位置。没有连接供应方真实地址、没有执行真实身份查询，也没有实现个人嫌疑分数、人员排名或自动批量筛选。

## 普通用户怎么用

1. 用原统一网址登录，进入“智能研判”。具备授权的账号会看到“盗窃资料查询”。无需知道工具名、Skill 编号或 API 路径。
2. 点击按钮，选择查询资料。先使用演练日期 **2026-09-20**，选定来源位置或演示对象。
3. 点击“检查范围”，确认资料种类、日期、对象/位置、半径和页码，再点击“确认并查询”。这一步才会发起一次用户请求。
4. 查看中文回答和“查看本轮来源与下一步查询”。执行完成与资料覆盖分别展示；“覆盖有限”不等于失败，也不等于查询到了全部资料。
5. 警情记录可点击“以此位置核对抓拍范围”；抓拍/预警记录可点击“核对选定对象轨迹”；有明确来源地点的轨迹可点击“以此地点核对警情范围”。每一步仍需检查并确认范围，不自动扩大范围。
6. 展开“人工来源复核”，填写“来源核对一致 / 需要补充资料 / 发现资料不一致”及意见，点击“追加复核记录”。更正使用“追加更正”，旧意见保留；报告附独立复核段。复核意见不改变代码事实。
7. 只解释历史资料时可以说“解释已有结果”“展开依据”或“说明资料缺口”。换对象或日期时重新使用范围表单；系统不会将未支持对象替换为演示对象。

当前授权给 `alignment-a`、`alignment-b`。管理员仍使用同一网址管理，六个插件没有独立的用户登录网址。密码、服务 Bearer、数据库密钥不进入本交接文档。

## 插件与资料契约

| 插件 | 工具 | 固定来源路径 | 核对注意事项 |
|---|---|---|---|
| peixian-theft-incidents | peixian_query_incidents | POST /jq/search | 半径转公里；处警时间不是案发时间 |
| peixian-theft-captures | peixian_query_captures | POST /jq/capture | 半径为米；限定来源人群的抓拍汇总不等于到访次数 |
| peixian-theft-tracks | peixian_query_tracks | POST /track/person | 明确单个对象；设备位置不证明人员精确到场；完整总量未知 |
| peixian-theft-warnings | peixian_query_warnings | GET /system/multiDimension/list | 顶层 rows/total；整日时间范围；类型数不是事件数 |
| peixian-theft-warning-detail | peixian_query_warning_detail | GET /system/multiDimension/idCard/{subject} | 来源标签不证明前科，不公开扣分字段 |
| peixian-theft-warning-logs | peixian_query_warning_logs | GET /system/multiDimension/logs/{subject} | 来源固定近7天窗口；不接受任意起止时间 |

六个包均为1.0.0，各自一个查询工具、独立服务连接；共同使用私网合成服务。模型只传 `{}`，Gateway 从本 Run 已冻结计划注入条件。模型不能改模块、地址或人员条件。健康检查不读取资料。

分页只查明确的一页，不自动翻页。每条响应行使用本 Run 的稳定行引用；不把缺少供应方稳定ID的问题掩盖成永久业务主键。图谱只建立对象与来源记录关系，不建立犯罪关系或推算距离。

两个新增官方模板是“警情与观测资料核对”和“观测与警情资料核对”，作为方法说明供用户复制。没有覆盖已有个人 Skill；本次实际取数验收走确认表单与冻结计划，未把模板发布等同于用户复制后模型调用的验收。

## 接口接入

详见同目录 `theft-provider-api.md` 和匹配运行版本 `openapi.json`。

主要新增接口：

- GET /api/console/v1/theft-provider/capabilities
- POST /api/console/v1/sessions/{sid}/provider-query/preview
- 现有消息提交增加 provider_query={plan,confirmation}，agent_id=theft-assistant
- GET/POST /api/console/v1/sessions/{sid}/runs/{rid}/reviews

消息使用 client_request_id，复核写操作使用 Idempotency-Key。未知受理结果先查询原会话，不能换新标识自动重发。确认签名绑定账号、会话、配置版本、上下文重置边界，600秒有效。

Result V2 保持原路径，新增来源合同/快照、冻结查询及插件版本；中文 answer 来自结构化回执。人工复核为本人资源；平台管理角色不因此获得用户正文读取权。

## 部署与回退

数据库升级至 schema v10，只增加追加式复核表及索引，保留原身份和资源归属。迁移要求维护冻结、无未终结 Run/环境任务/执行责任、匹配备份及显式升级开关。旧 v9 镜像不能直接读取新库。

本轮先完成数据库副本演练，再停止写入、Worker及两个账号组件，制作包含7个持久卷及宿主配置/密钥/发布记录的完整备份，事务升级并发布匹配 Control/Gateway。重启后的恢复责任由 Worker 在修复模式核对，归零后才恢复 normal。没有手改运行门禁或伪造停止状态。

回退优先使用兼容 v10 的版本；撤销功能可先关闭新能力入口并停用对应授权/安装，按原配置发布流程生效。若必须恢复 v9，只能把本轮完整备份恢复到另一个空目标，先保留升级后的新增 Run/复核/文件，不降低 user_version、不覆盖新数据。数据库副本演练不等于完整容器/持久卷恢复演练；后者本轮未执行。

插件包可用 `python3 deploy/peixian/examples/theft_provider/package.py <新的输出目录>` 重建。服务使用私网显式地址和单独只读 Bearer 密钥文件启动，示例代码在同目录 `service.py`；不应绑定公网或把凭据写进包中。源码版本、镜像和完整备份清单保存在受保护发布目录。

## 真实接口接入前仍需解决

- 供应方登录密码明文与RSA描述冲突；认证成功/失效/续期契约需确认。
- 警情与轨迹资料的授权范围必须由真实服务落实，匿名上游也不能变成平台任意查询入口。
- 坐标系、空间筛选含义、处警与案发时间、跨小区时间参数、夜间明细结构和稳定轨迹点ID仍需供应方确认。
- 23:00–05:00来源夜间规则与既有22:00–06:00口径需分别版本化，不能互相覆盖。
- 未接真实资料，也没有执行并发、持续负载或目标生产容量验收。
