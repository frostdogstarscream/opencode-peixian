# 第四轮前后端联调接口说明

日期：2026-09-22。入口：https://36.134.45.38:19460/ ，同源前缀 `/api/console/v1`。数据库仍为 schema 9。

## 1. 本轮接入方式

已保留前端同事当前页面、背景、字号、颜色、布局及图谱刷新修复，在该版本上增加消息附件持久读取和图谱状态说明。服务器原 `frontend-alignment` 工作区没有被覆盖；匹配候选源码在 `stage2-task-spec-v1`，分支 `codex/frontend-contracts`。CSS 与发布前同事工作区逐文件哈希一致。

认证、Cookie、CSRF、角色、会话归属和既有请求标识不变。消息写入使用 `client_request_id`，管理写入使用 `Idempotency-Key`；通知后读取快照，不自动重放生成请求。

## 2. 消息附件

`GET /sessions/{sid}/messages` 的本人用户消息新增：

```json
{
  "info": {"id":"message-id","role":"user","run_id":"run-id"},
  "parts": [],
  "attachments": [{"id":"file-id","name":"联调附件.txt","status":"available"}]
}
```

- 元数据取自受认证 Gateway 文件查询，并随本轮加密请求快照冻结；不接受客户端自行声明文件名。
- `name` 是提交当时的名称，去掉路径和控制字符；之后改名不改变历史名称。
- `available` 表示控制侧保有该账号文件元数据，不能替代下载时的实时可用性检查。
- 经平台删除后保留冻结名称，`status=unavailable`，下载返回 404。
- 历史 Run 未冻结可靠映射时返回 `[]`，不从隐藏提示或正文猜测名称，不补写历史记录。
- 同一个请求标识重放返回原受理结果，沿用原附件快照；显式新 Run 重新进行当前授权校验。
- 当前前端优先使用 `message.attachments`，旧接口无字段时才使用页面内临时映射。复用原有附件 chip，没有新增样式。
- 返回的是元数据，不含文件正文、服务器路径、签名 URL 或其他账号附件。

跨账号请求会话、Run、证据、文件均拒绝。文件列表缓存存在与物理文件存在不能混为一谈。

## 3. 线索摘要与逐项来源

结构化 `analysis_result` 仍为 1.0；保留 `clues[].headline/summary/discoveries/evidence`，兼容新增：

```json
{
  "headline": "取得 12 条原始资金流水。",
  "summary": "观察范围及本轮已取得资料的日期范围、数量说明。",
  "discoveries": ["按原始字段统计的事实要点"],
  "discovery_details": [
    {"text":"事实要点","source_ids":["demo1"],"category":"metric"},
    {"text":"统计局限","source_ids":[],"category":"limitation"}
  ]
}
```

内容由服务端根据本轮已核对记录确定性生成，不使用模型自由文本填补事实。标题保持简洁，摘要补充观察范围、覆盖日期、缺失时间；发现最多四项。只对带时区时间换算北京时间并统计自然日。资金不合并双边流水，`credit/debit` 按已核实合成服务字段解释为收入/支出；其他未识别值保留未知，不猜测方向。

原抽屉继续渲染 `summary/discoveries/evidence`，无需另一套页面。新增 `discovery_details` 供后续精确来源跳转；本轮未强制增加新的跳转控件。历史持久结果不原地回填，旧摘要仍可能保持原样。

## 4. 图谱

沿用 `/sessions/{sid}/runs/{rid}/graphs` 及已有快照、节点、展开、路径接口。页面稳定地以会话 ID、Run ID、修订变化为加载边界；普通数据刷新不清空画布。

`partial` 且零节点表示当前没有满足批准条件的可绘图来源关系。现在说明“没有图谱不表示没有记录”，不使用示例图补齐。车辆历史 Run 的事实记录已存在，但缺少批准的记录级 claim，仍为待补核对链路；本轮没有放宽信任边界，也没有重算该历史结果。

## 5. 管理恢复接口

`POST /admin/recovery/{uid}` 新增 `action=retry`：

```json
{"action":"retry","state_version":123}
```

仅超级管理员，要求 CSRF 和 `Idempotency-Key`；必须在 `repair_only` 模式。按状态版本检查并复用同一失败恢复责任及冻结快照，不直接清空恢复标记，不放开安全阻断，不覆盖停用/暂停意图。正常受理 HTTP 200，响应 `accepted=true` 与 job。状态变化或恢复责任不明确返回 409，字段非法返回 422，管理员和普通用户返回 403。

Worker 先校验并恢复该 Runtime 管理网连接，再查询真实启动身份、关闭入口并核对活动与版本。退出修复模式时，对已修复但仍关闭的环境补排重新核对任务；只有新观测通过后才允许 `ready/open`。旧成功回执不能直接用于重开入口。

## 6. 联调建议

1. 使用普通账号新建会话，上传文本并发送，确认标签属于对应用户消息。
2. 刷新、重新登录再查看；删除测试文件后确认名称仍保留、下载不可用。
3. 新建合成资金查询，检查 12 条来源与摘要/核心发现。旧 Run 不要求自动更新文案。
4. 打开图谱，验证断线恢复、缩放、拖拽、路径和放大窗口。
5. 用另一账号访问相同资源 ID，应返回 404。
6. 不将 `Run completed` 等同于已取数。场景校验直接回复时也可能正常结束，必须检查真实工具结果与证据。

剩余范围：390 像素原有背景导航占位挤压正文；车辆历史事实批准不足；partial/no_text/超限文件专项、长时间断线高峰、并发和真实资料源未在本轮验收。
