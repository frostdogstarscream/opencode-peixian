# 普通对话未选 Skill 仍调用技能：后端排查报告

日期：2026-09-20\
范围：`/root/PeiXianDB/frontend-alignment` 当前部署；仅做源码及正式控制库只读检查，未修改后端。

## 现象与证据

- 最近 29 条 Run 的脱敏调用记录中，22 条 `selected_skills=[]`；其中 3 条仍出现真实 `run_events.step_type=skill`、“使用技能”步骤。`run_scheduler.py` 仅在模型工具调用的 `tool == 'skill'` 时记录该步骤，不是前端凭空渲染。
- 至少两条上述 Run 同时满足 `selected_skills=[]`、`selected_plugins=[]`，却有 Skill 步骤和实际插件调用。示例 Run ID 前缀：`8cc41272`、`ccf93d45`。仅用前缀定位，未导出提问内容、模型回答或凭据。
- `control/app.py` 的消息受理只在 `skill_ids` 非空时添加“请使用已启用的技能”前导提示；前端空选择发送的也是空数组。故本现象不能归因于前端把 Skill ID 隐式塞入请求。
- `control/worker_api.py` 为运行环境配置 `skills.paths=["/managed/skills"]` 且全局 `permission.skill="allow"`；运行配置包含该账号**所有**已启用 Skill，`deploy/peixian/console-runtime.py` 将其发布到同一 Agent 环境。模型因此在未选 Skill 的 Run 中仍可调用已安装 Skill。

## 前端已处理

前端原先在切换已有会话和发送成功后保留 Skill/插件/文件选择，可能造成后续提问意外沿用旧选择。本轮已改为切换会话清空、消息确定受理后清空；提交结果不确定时保留选择和草稿，避免误导用户或自动重发。该修复只消除前端选择残留，不能代替后端执行隔离。

## 建议后端修复

1. 明确产品契约：若 Skill 必须由用户本次显式选择，`skill_ids=[]` 的 Run 应禁止调用 `skill` 工具；非空时按本次 Run 的 ID 快照做服务端 allowlist 校验，不依赖提示词限制。空选择时最好不要把可发现的 Skill 列表注入该次模型上下文。
2. 运行环境可继续安装账号已启用 Skill 供其他请求使用，但调用网关/工具权限必须按 **Run** 隔离。不能仅按账号“已启用”授权。
3. 明确插件契约：现有 v6 文档把 `plugin_ids` 定义为偏好而非严格白名单；如业务预期“未选插件就不得调用”，需另立严格模式及相应后端权限控制。当前空插件选择下也观察到实际插件调用。
4. 增加回归：同一账号对同一问题分别提交空 Skill、指定 Skill、取消 Skill 后再提交，断言请求记录、实际工具调用、Run 步骤与回答均符合选择；并检查历史会话上下文不会把上次 Skill 指令带到新 Run。

建议优先级：**高**。这不是页面显示问题，而是用户意图与模型实际能力边界不一致；涉及研判结果可信度，也可能触发未预期的插件/资料访问。建议在下一轮业务验收前修复并回传测试结果。
