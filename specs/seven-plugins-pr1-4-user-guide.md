# 七个独立资料插件与 V3 方法使用说明

## 普通用户

登录原网址，继续使用自己的账号和个人空间。无需创建项目，也无需输入内部场景编号。

“我的插件”中七项资料能力分别为：资金资料、话单资料、人像共现资料、综合关联资料、夜间活动资料、车辆资料、关联互查资料。各自有安装、启停与连接测试，平台公共接口和凭据由超级管理员管理。连接测试只检查服务健康，不等于模型已经查询资料。

“我的技能”中的四项专项方法是：夜间活动整理、同行与共现核对、资金往来整理、已有关系核对。另保留涉赌和盗窃总流程。V3 是内容版本，不要求把 V3 输入提问。用户自行编辑的旧副本不会被覆盖；旧副本不可用时，应选择新的官方方法，不要反复重发请求。

## 建议的提问

- 选择“涉赌案件资料整理”：整理当前已接入场景的夜间活动、同行、资金和已有关系，给出对应来源及资料缺口。
- 选择“资金往来整理”：整理当前场景的原始资金流水，说明金额单位，列出两条流水及来源，不合并交易。
- 选择“同行与共现核对”：区分哪些记录明确同行、哪些只有同框，哪些不能判断，并给出来源。
- 同一会话继续问：本轮只展开资金资料，按代码事实核对后简短说明，不查其他模块。
- 选择“盗窃案件时空资料核对”：核对当前场景的时间、观测、车辆和已知地点关系，列出可以确认与不能判断的内容。

当前是固定合成资料场景。这些接口不支持任意身份证号、真实人员、任意时间范围的查询；换对象不能悄悄使用固定对象资料代替。

## 如何判断执行结果

Run 完成表示这轮执行结束，并不自动代表所有资料或模型摘要都通过核对。查看实际插件步骤、事实资料完整性、摘要核对和来源；只出现文字回答不能当作取数成功。

代码事实中“已取得零条”“未取得”“失败”“结果未知”含义不同。需要两个模块的方法只取得一个时，应显示缺口。模型没有发起查询时，不能凭它的文字生成可信卡片。

事件图来自当前 Run 的代码事实。时间箭头表示先后，不表示因果；同框不等于同行，缺少同行记录不等于独行，资金往来不表明交易用途。存在有效事实时自动展示，不需要额外要求画图。

## 管理员与超级管理员

普通管理员仍负责既有账号、模型及允许的管理记录。七个插件和公共方法治理、服务连接配置仍由超级管理员负责。拆分不会扩大普通管理员权限。

七个插件分别绑定出口层受限连接。公共查询路径虽相同，每个连接还检查固定 JSON module，不能通过改请求体跨模块取数。健康检查不取业务资料。普通用户不获得服务凭据。

内部场景、事实整理与摘要核对工具不作为第八个插件出售或安装。它们由平台维护，逐次检查当前 Run 的能力计划和账号授权；先记录调用责任，再请求插件。成功结果只在同一 Run 内复用，失败或未知不自动重发。

## 历史及回退

旧七合一插件已经不可安装，发布包留存归档。历史 Run、报告、事件图不依赖重新安装旧插件，也不会被新数据重算。查看之前候选验收结果时，请对照验收回执中的已知缺口；不要把旧候选结果当作最终修复后的新执行。

迁移和回退仅由可信宿主操作工具执行。不要删除用户数据卷，不要恢复整库覆盖新会话，不要把私人修改的 Skill 批量替换。
