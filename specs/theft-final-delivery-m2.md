# M2 任务与来源关联候选交付

本阶段在 M1 ef7dbda 基础开发，未迁移线上数据库、未调用真实资料服务。

## 数据与接口

新增 schema v11 的 analysis_tasks / analysis_task_steps，以账号和会话为边界，将既有业务 Run 组成一个任务。敏感任务内容、来源与参数继续加密保存。任务方向仅是步骤元数据，不改变账号权限或要求新会话。

POST /api/console/v1/sessions/{sid}/scenarios 创建任务，GET 同路径/{scenario_id} 读取任务、步骤与分项预算。v2 查询预览增加 analysis_task_id、context_version、step_request_id、source_refs 和可选 direct_parent_run_id。来源引用包含 run_id、result_digest、record_id、snapshot_id。一个步骤只使用一个明确来源位置；多个位置必须串行。

来源坐标和人员从保存的原始响应及匹配投影读取，客户端不能替换。坐标兼容合同未确认时拒绝衔接；多个候选不得默认选第一条。任务版本 CAS、Run、投递记录与来源关系在同一事务提交；重放返回原 Run。预算耗尽回滚整笔受理。实际投递前再次核对来源、权限和配置。

## 迁移

v10→v11 使用新的迁移编号、结构指纹和脚本摘要，不改变既有迁移。非全新库必须显式允许迁移且处于冻结、无活动执行和宿主变更状态。旧 MAX_SCHEMA_VERSION=10 程序拒绝 v11。副本测试保留历史结果摘要，失败事务回滚，恢复目标不覆盖在线新增数据。
